# vive-audit — 独立監査

シミュレーションの要所で、成果物を独立監査官（氷室 律ペルソナ）の立場で監査する
スキル。監査官の人格・チェックリスト・報告書式は、このスキルと同じフォルダの
[auditor.md](auditor.md) にある。

**作業した本人が自己申告で「問題ない」と言うのを防ぐ**のが目的である。
そのため、監査はできる限り**作業した会話とは別の文脈**で行う（下記の手順2）。

## 引数

- 監査対象: scene.yaml のパス（必須）。加えてあれば run の出力ログ
  （テキストで渡す）、dose.npz のパス、使用者に出す予定の報告文案、
  `runs/<シーン名>/requirements.md`（vive-interviewが書き出したヒアリング要件記録）。
- 未指定なら、この会話で直近に扱ったシーン・結果を対象にする。
  `runs/<シーン名>/requirements.md` が存在するならステージAで必ず渡す
  （scene.yamlの物理的な正しさだけでなく、使用者が実際に頼んだ内容との
  一致を検証できるのはこのファイルがある場合のみ）。

## 手順

1. **ステージを判定する**。渡された成果物から監査ステージを決める:
   - scene.yaml のみ → ステージA（シーン監査）
   - run 出力 / dose.npz あり → ステージB（実行結果監査）
   - 報告文案あり → ステージC（報告文監査）
   複数該当なら該当ステージを全て実施する。

2. **監査を実行する。独立性の高い方法から順に、使えるものを選ぶ。**

   - **(a) 別の文脈で実行する（推奨）**: 作業した会話の記憶を持たない別の
     実行単位に監査させる。使っているAIに応じて、次のいずれかを使う。
     - サブエージェントを起動できる場合はそれを使う（Claude Code では
       `vive-auditor` というサブエージェントが定義済み）。
     - 非対話の別プロセスを起動できる場合はそれを使う（例: Codex の
       `codex exec -s read-only "<依頼文>"`）。
     - どちらもなければ、使用者に「新しい会話で次の依頼文を実行してください」
       と依頼文を渡す方法でもよい。

     依頼文には必ず含める:
     - 「まず `.claude/skills/vive-audit/auditor.md` を読み、その人格と手順に
       完全に従うこと」
     - リポジトリルートのパスと、監査対象ファイルのパス
     - `runs/<シーン名>/requirements.md` があればそのパス（ステージAでは必須級。
       ないなら「要件記録なし」と明示する）
     - run 出力ログの全文（別の文脈からは会話中のコンソール出力が見えないため）
     - 監査ステージ（A/B/C）
     - 「実装・修正は禁止、監査報告書の書式で返答」という念押し

   - **(b) 同じ会話で実行する（別の文脈が使えない場合のみ）**: [auditor.md](auditor.md)
     を読み、該当ステージのチェックリストを自分で実施する。このとき:
     - 自分の作業の記憶を根拠にしない。全項目を、コマンドの再実行と
       一次データ（xraylib、`chatcarlo/data/` のCSV、出力ファイル）で確かめる。
     - 報告書の冒頭に「同一セッションでの監査（独立性は限定的）」と明記する。
     - 確かめきれない項目は「未確認事項」に入れ、合格に数えない。

3. **監査報告書をそのまま提示する**。要約して丸めず、判定・所見表・
   独立検証・未確認事項を使用者に見せる。判定を書き換えない。

4. **差し戻しの場合**: 所見に沿って修正した後、**同じ観点で再監査**する。
   合格が出るまで結果を使用者への最終報告に使わない。

## vive-check との連携

vive-check の関門で以下のタイミングに挟む（使用者が監査を明示的に
断った場合は省略可）:

- 関門1の承認前: ステージA監査 → 所見を添えて使用者に確認
- 関門3の直後（結果提示前）: ステージB監査
- 最終報告の直前: 数値を含む報告文案に対してステージC監査

## 注意

- 判定が「差し戻し」でも最終判断は使用者にある。判定を隠さず提示した上で
  「このまま進めるか」を確認するのは可。
- 監査の指摘が誤っている（一次データと照合して反証できる）場合は、
  反証の根拠を添えて再監査に回す。水掛け論は使用者に裁定を仰ぐ。

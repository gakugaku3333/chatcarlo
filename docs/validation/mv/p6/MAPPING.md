# P6 の移植対応

元の核・表・物理・乱数実装は変更しない。P6 は `P5jState` をメンバーとして保持し、
`p5j_init` の後に発散線源を設定する。particle / charged のみを写して採点呼出しを追加する。
行番号は今回追加したファイルのもの。

MT (`p6_cpu.cpp:p6_mt_run`) は一度だけMTを初期化して履歴を番号順に完走させる。
領域は付与ごとに当該群へ直接加算し、制動放射の `brems[1]` も付与ごとに全体へ直接加算する。
履歴ごとの付与記録はP3bと同じ9列で、別配列にsite 1…5を記録する。

追補2のCPU検査では、付与呼び出しごとにsite 1…5の件数も数える。
件数は記録容量と独立なので、gate1では付与配列を確保せずにバッチ0・2・99の各件数と合計を報告する。
0cは通常の2,000履歴でsite 1…4の通過を求め、site 5は別の固定電子状態を
P3bの `source_state` とCPUの検査専用入口へ渡して付与記録を比較する。
検査専用入口はスペクトル・照射野の乱数を引かず、P3bと同じく制動放射の残り時計だけを引き直す。
その後は通常の `p6_transition` で完走させ、付与処理や記録の値は作り直さない。

PhiloxのCPU履歴経路 (`p6_histories`) とGPUは同じP6Slotと局所シンクを使う。
GPU (`p6_gpu.cu`) はP5k Fのballot＋完了時の補充を写し、履歴の最後に局所出力をatomicで100群へ加算する。
CPUの参照用集計 (`p6_run`) も同じ履歴内加算を使う。
配列を消し忘れる故障は、付与時の収支と独立に、出力された板の配列の和と付与総量の一致でも検出する。

外側バッチの履歴範囲・種は `p6_core.contract` に集約する。
関門3: 種20291960、バッチbは `[100000*b,100000*(b+1))`。
本番: 種20291764、バッチbは `[460000*b,460000*(b+1))`。
再開時も同じ契約・コード・設定・配列ハッシュを照合する。

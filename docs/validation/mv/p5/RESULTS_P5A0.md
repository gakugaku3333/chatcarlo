### 読み取れること（P5aの詳細計画に使う）

1. 乱数・整数演算・表の読み出し・スタック・原子的な加算は、GPUとCPUで完全に一致する。並列の集計とスレッドの割り当ては履歴ごとの比較を壊さない。
2. **積和の融合は `--fmad=false` で切れる**（切らないと四則の式の16%が食い違う）。
3. 数学関数（log 以外の超越関数）は、GPUとCPUで最後の1ビットが違う点が多い（6〜27%）。**機械が違えばCPUどうしでも違う**（X1b）。したがって、
   - 鎖0（P4の核との完全一致）は、Numbaと同じ機械（手元のM3）のCPU版でしか成り立たない。
   - 鎖2（CPU版とGPUの履歴ごとの比較）では、輸送の途中で分岐が入れ替わる履歴が出ると見込まれる。骨子2-3のとおり、合否は対の差で決め、一致の割合は報告のみとする。
4. 小さい履歴でのGPUの速さはCPUの1スレッドの約4.7倍にとどまった。1スレッドあたり約3 kBのスタックを持つ作りなので、輸送の核でも同じ程度の制約が出る可能性がある（未確認。P5dで測る）。

## Claude による関門 1・2 と測定（2026-10-24）

**結論: 関門 0〜2 にすべて合格。P8g-1 は検査した履歴（関門 1・2 の範囲）で P8f と履歴ごとにバイト一致し、採用の方針に従って P8f の判定 A・B の合格を引き継ぐ（全履歴の同一性の証明ではない。P8f の合格範囲を他の積層・照射野・境界近くのビンへ広げない）。T4 で 1.25〜1.31 倍。**

- 関門 1（M3、3 分）: CPU の P8g と CPU の P8f が 20,000 履歴（start 0）・2,000 履歴（start 7,000）で履歴ごとの全出力バイト一致。保存済み P8f 参照（`p8f_ref_gate2`、`p8f_ref_batch_000/050/099` の集計、`seconds` を除く）ともバイト一致。f2 は履歴 10,141 で拒否（`gate1.json`）。
- 関門 2（T4、`t4/`）: 2a CPU–GPU、2b 同じ VM の GPU の P8f と 20,000 履歴バイト一致、2c・2d 40×128 と 40×256 の集計と補充の境目、2e 検査ビルド（無効な読み出し 0、通常版・検査版・P8f 一致）、2f GPU の部品の照合と故障（f1 は部品比較で拒否、f3 は無効な読み出し 60 で拒否）。すべて pass。
- 1 回目の T4 は 2f の合成格子の試験で `CUDA_ERROR_LAUNCH_FAILED`。検査ビルドの読み出しの数え上げ（GPU では `atomicAdd`）が、その試験の核ではスレッドの局所配列 `reads[37]` を指していたため（局所メモリへの atomic は GPU で不可。CPU では起きない）。Claude が `p8g_colab.py` の 1 行を変え、合成格子の試験を通常ビルドで回すようにした（検査ビルドの部品比較は残す）。`p8g_colab.py` は核の指紋の外なので関門 0・1 は有効。書き出し直して 2 回目で合格。

### 速さ（T4、同じ VM で交互に 3 回、核の時間の中央値、µs/履歴）

| 構成 | 20,000 履歴 | 200,000 履歴 |
|---|---|---|
| P8f 40×128（P8f の本番の起動） | 334.7 | 277.2 |
| P8f 40×256 | 307.6 | 259.6 |
| P8g 40×128 | 262.0（×1.28） | 221.1（×1.25） |
| **P8g 40×256** | 243.1（×1.27） | **198.4（×1.31）** |

- 倍率は同じ起動の P8f に対する比。P8f の本番の起動（40×128、200,000）に対しては P8g 40×256 で ×1.40。
- 資源: P8f 212 レジスタ・ローカル 33,808 B、P8g 234 レジスタ・ローカル 34,112 B。常駐ブロック/SM は 128 スレッドで 2、256 スレッドで 1。P8g の初期化（表の定数 log の計算）は 137 ms で、核の時間に含めない。
- 1×10⁸ 履歴の核の時間の見込み: P8g 40×256 で約 5.5 時間（P8f の本番の起動では約 7.7 時間）。

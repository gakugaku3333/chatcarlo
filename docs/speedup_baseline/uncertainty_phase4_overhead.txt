## (D) 条件1: CPU時間(user+sys)での再測定 — 熱ドリフトで中断

スリープに強い指標としてCPU時間へ切り替えたが、持続負荷でマシンが熱劣化し、
判定に使えなかった。

  cond1 rep1 baseline  real=28.95s cpu=28.83s
  cond1 rep1 unc_off   real=32.70s cpu=32.53s
  cond1 rep1 unc_on    real=36.20s cpu=36.12s
  cond1 rep2 baseline  real=36.76s cpu=36.66s   <- rep1 baseline の +27.2%

  同一の baseline コードが連続する2反復で 28.83s -> 36.66s と単調劣化。
  かつ rep1 内の baseline -> off -> on の単調増加が**実行順序と完全に一致**
  しており、熱ドリフトと arm 効果が交絡している（arm順序を固定して回した
  計測設計そのものの欠陥）。ここで中断。

  → 今後この種の測定をするときは (i) 同一セッション内ペア比較で基準を定義、
    (ii) 反復回数と許容ばらつきを事前に決める、(iii) arm順序を反転/ランダム化
    して熱ドリフトと交絡させない、の3点を計測設計に必ず入れること。


## (E) メモリ: 設計判断6の見積り（36バイト/voxel増分）の裏取り

グリッドメモリが支配的になる細解像度条件で測る必要がある。
条件: chest_room.yaml, n=1e5, --dose-grid --resolution 2, workers=1
      グリッド形状 (250, 250, 198) = 12,375,000 voxel

  統計OFF peak memory footprint  2,767,112,640 B
  統計ON  peak memory footprint  3,234,695,928 B
  差 467,583,288 B / 12,375,000 voxel = 37.78 バイト/voxel
  設計判断6の見積り 36 バイト/voxel（kerma_sum2 + h10_sum2 + n_batches_hit(int32)
  + スナップショット2枚）と 5% 以内で一致 → 裏取り成功。

  注意: このOFF側の実行は壁時間がスリープで汚染されている（real 642s /
  user 6.17s）。ピークメモリはスリープの影響を受けないため値は有効だが、
  **同じ実行から壁時間を読んではいけない**。

  既定解像度（n=1e6, resolution=5cm, 790,000 voxel）での同じ引き算は
  86.7バイト/voxel相当となりノイズが大きい（輸送側の光子バッチバッファ等が
  グリッド差分に対して無視できないため）。理論値検証は対象量が支配的になる
  条件を選んで測ること。

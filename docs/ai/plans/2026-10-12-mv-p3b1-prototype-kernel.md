## 実装方針

### 1. `scoring_p3b.py`（幾何だけ。乱数も物理も持たない。すべて `@njit`）

- `clip(p0, p1, lo, hi) -> (t0, t1)`: 線分 `p0 + t (p1 − p0)`（t∈[0,1]）が、軸に平行な箱 `[lo, hi]`（3成分）の中にある範囲。空なら `t0 >= t1`。成分の変位が0の軸は「その成分が箱の中かどうか」で判定する。箱の面の扱いは半開区間（`lo ≤ 座標 < hi`）で統一する。
- `score_box_bins(score, p0, p1, loss, axis, origin, width, lo, hi)`: 箱でクリップした範囲を、`axis` 方向に `origin` から `width` 刻みの区画へ、**線分全体の長さに対する割合**で配る（`loss × (その区画の中のtの長さ)`）。箱の外の部分は配らない。配った合計を返す。線分の長さが0（`p0 == p1`）のときは点の沈着として扱う。
- `score_box_point(score, p, loss, axis, origin, width, lo, hi)`: 点が箱の中なら、その区画に入れる。入れた量を返す。
- 深さの近道（`abs(z1-z0)<1e-15` なら点）は使わない。tの長さで配るので、深さの変位が0でも横の区画に正しく配られる。

### 2. `photon_transport_p3b.py`（P3tの写しに、次だけを足す）

1. **位置**: 光子の飛行で `a[0]`、`a[1]` も更新する。前提事実に挙げた全部の発生箇所で、子の `a[0]`、`a[1]` に親の値を入れる（`photon_state`・`initial` の写しに位置の引数を足すか、作った直後に代入する。311行と同じ形）。
2. **線源**: 引数 `field_half=None`、`ssd=None`。両方が与えられたときだけ、スペクトルの乱数の**あと**に乱数を2個引き、`x=(2u−1)·field_half`、`y=(2v−1)·field_half`、向きを `(x, y, ssd)/|…|` にして、`z=0` から出発させる。与えられないときは乱数を引かず、原点・+z（P3tと同じ）。`field_half` を与えられるのは光子の線源（スペクトルまたは単色）のときだけで、`source_state`・荷電粒子の線源と一緒なら `ValueError`。試験用に `source_offset=(x0, y0)`（入射点に足す、向きは変えない）を持つ。
3. **深さの区切り**: 引数 `dz=.2`、`dz_fine=.05`。既定値ではP3tと同じ。板の厚さがどちらかの倍数でなければ、入口の関数で `ValueError`（P3tの0.2 cm固定の検査を置き換える）。
4. **領域の集計**: 引数 `regions=None`。与えられたときだけ集計する（与えられないときは、返り値の先頭15個がP3tと同じ）。`regions` は数値だけの配列で、中身は「直方体の半幅、側方分布の半幅（直交方向）、走査の範囲、走査の刻み（粗・細）、深さの中心（3つまで）、深さの厚さ」。返り値に次を足す（どれも核の内側の100バッチごと）:
   - `axis_coarse` (100, 厚さ/dz)、`axis_fine` (100, 厚さ/dz_fine): 中心軸の直方体。
   - `profile` (100, 2, 深さの数, 区画数): 走査方向 x・y。区画は符号つきの座標で −範囲〜+範囲（重ね合わせは解析の仕事。核では重ねない）。`profile_fine` は細かい刻みの版。
   - `region_ledger`: 履歴ごとの検査の違反の数（下の5）。
   - 沈着のたびに、既存の深さの集計に加えて、`score_box_bins`（荷電粒子の1歩: `(x0,y0,z0)` から歩のあとの位置まで）または `score_box_point`（点の沈着: その時点の `a[0],a[1],a[2]`）を各領域に対して呼ぶ。
5. **履歴ごとの検査**: 各領域に配った量の合計が、その履歴の沈着の総量を超えない（丸めの範囲 `1e-9 × 入射エネルギー`）。超えたら `region_ledger` を増やす。
6. **記録の仕組み（試験用）**: 引数 `record_deposits=0`。正の数 M を与えると、沈着を先頭から M 件まで `(履歴の番号, 種類(0=線分,1=点), x0,y0,z0, x1,y1,z1, 量)` として配列に記録して返す。あふれた数も返す。記録の有無で、乱数の消費と他の返り値が変わらないこと。
7. 乱数の順序・回数、物理の式、刻みの規則、カットオフには手を入れない。

### 3. `batch_kernels_p3b.py` と登録

- `'p3b_field'` の `run / keys / healthy / fingerprint / check_params` を定義する。`params` は `E`、`backend`、`brems_mode`（1か2）、`spectrum`、`field_half`、`ssd`、`dz`、`dz_fine`、`regions`（数値のリスト）。縮約はP3uの `'p3t_slab'` と同じ考え方（内側の100バッチの軸で和。足した領域の配列も同じ）。`healthy` は `'p3t_slab'` の条件に「`region_ledger` が0」を足す。`fingerprint` は `'p3t_slab'` と同じ項目。
- `batch_kernels_p3u.py` の末尾で `KERNELS['p3b_field']` を登録する。モジュールの読み込み時に `photon_transport_p3b` を import しない形にする（関数の中で import）。
- **ハッシュの扱い**: `batch_runner_p3u.SOURCES` には `photon_transport_p3b.py` などが入っていない。`fingerprint` に `photon_transport_p3b.py`・`scoring_p3b.py`・`batch_kernels_p3b.py` のsha256を入れて、これらが変わった再開を拒否できるようにする。

### 4. `run_p3b1.py`（統計を使う検査と時間の報告。Claudeが実行する）

`python -m prototypes.mv_electron.run_p3b1` で、下の B7・B8 と時間の報告を行い、`docs/validation/mv/p3b/checks_p3b1.json` に書く。種と粒子数はスクリプトに固定する。作業フォルダは `CHATCARLO_P3B_CACHE`（既定 `~/.cache/chatcarlo/p3b`）。すでに結果があれば、計算し直さずに止まる。

### 詳細レビューの反映（上の記述と食い違う場合は、この節が優先）

1. **既存の15個の出力の処理はそのまま残す。** 深さの集計（`tracked_segment`／`tracked_local`／`add_clear`）は書き換えず、新しい領域の集計と記録を**並行して足す**（演算の順序が変わるとバイト単位の一致を失うため）。したがって実装方針2の3（`dz`・`dz_fine` の引数化）は次のようにする: 既存の2つの深さの集計は0.2 cm・0.05 cmのまま残し、**板全体の0.25 cm刻みの集計は、新しい領域の1つ（横の範囲が無限の箱。試験専用ではなく本番でも使う）として足す**。板の厚さは0.2 cmと、領域の深さの刻みの両方の倍数であること。
2. **新しい核の `brems_mode` は1か2だけ**（入口で拒否。mode 0はP3sへ委譲する経路で、位置も領域も持たない）。
3. **位置を受け取る作成関数に統一する。** `photon_state`・`initial` の写しは `x, y` を引数に取り、既存の乱数を引く処理の順序を保ったまま、最後に位置を入れた完成した状態を返す。作成のあとで位置を代入する書き方はしない。B2は、この作成関数（Pythonの版）を包んで、返ってきた完成した状態を検査する。包む対象と時点: `_run_coupled.py_func` を動かし、モジュールの属性として参照される作成関数を `monkeypatch` で差し替える（`test_p3r.py` の `test_large_k_cutoff_closes_ledger` と同じやり方）。**対生成と2種類の消滅は、両方の子を検査する。**
4. **沈着は共通の入口（線分用・点用の2つの関数）に渡す。** 記録と領域の集計が同じ幾何を受け取る。領域の集計は内側のバッチの配列へ直接足し、履歴ごとの検査には領域ごとの合計だけを持つ（履歴ごとに全区画の配列を作らない）。箱の境界と区画の数は入口で一度だけ展開する。
5. **`region_ledger` の単位**: 箱ごと（直方体の粗・細、板全体、走査方向×深さの層×刻みのそれぞれ）に、「その箱に配った量 ≤ その履歴の沈着の総量 + `1e-9 × 入射エネルギー`」。板全体の箱は「= 総量」（同じ許容）。
6. **領域の原点**: `regions` に横の中心 `(cx, cy)` を持たせる（本番は0）。
7. **線源の関数**: 入射点と向きを作る部分を小さな `@njit` 関数 `sample_field(field_half, ssd)` にし、核はこれを呼ぶ。B7はこの関数そのものを検査する（検査用に別の式を書かない）。核には、先頭 `record_sources` 件の初期状態（x、y、z、向き、エネルギー）を返す記録も足す（`record_deposits` と同じ扱い: 乱数と他の出力を変えない）。
8. **引数の検査（`ValueError`）**: `field_half` と `ssd` の片方だけ／非有限／0以下、領域の配列の長さ違い・非有限・幅や刻みが0以下・走査の範囲が刻みの整数倍でない・深さの層が板の外、`record_*` が負。
9. **登録の変更の影響**: `batch_kernels_p3u.py` を変えると、変更の前に作った並列実行の作業フォルダ（P3uの時間測定のもの）は、ソースのハッシュの不一致で再開できなくなる。P3uの測定は完了していて再開の必要がないので、これは受け入れる（骨子の「変更禁止」の一覧は、この計画で上書きする）。

## 追補1（2026-10-12、B8の不合格のあと。診断の実行の前に記載）

**起きたこと**: 試験（B1〜B6、B9、B10、B3b、B3c、B5b、B9b）はすべて合格。`run_p3b1.py` はB7合格（p = 0.52、向きの誤差0）のあと、**B8が不合格**で止まった。9個の対比のうち1個（深さ10 cm、+y対−y）が z = −3.59（限度2.77）。他の8個は |z| ≤ 1.87。この判定は `docs/validation/mv/p3b/checks_p3b1.json` に記録されたまま残し、書き換えない。種を変えたB8の測り直しはしない（停止条件どおり）。時間の測定はB8の停止で実行されなかった。

**保存済みのデータから分かったこと（測り直しではない）**:
- 対比の精度が粗い。200万粒子では、片側の平均の差のSEMが約2%で、不合格の対比の差は −7.4%、他は −3.5〜+2.4%。
- 深さ10 cmの層だけで起きていて、同じy方向の深さ5 cm（−0.7%）と20 cm（+2.4%）には出ていない。輸送の物理や方位角のサンプリングの偏りなら、全部の深さに出るはずである。
- 9個で補正した偶然の確率は、t検定で約0.5%、順位の検定で約1.3%。偶然としては珍しいが、起こりえないほどではない。
- **速さ**: 領域の集計を入れた200万粒子の実行は、バッチの中央値で697 µs/粒子（P3uの平板は242 µs）。約2.9倍で、「1.5倍を超えたら報告」の条件にあたる。

**診断D1（B8の再判定ではない。原因が偶然か、実装の偏りかを、別の、検出力の高い量で調べる）**:
- 本番の条件、`photon_transport_p3b.run_coupled` を直接呼び、`record_deposits` で全部の沈着を記録する。2,000粒子 × 1,000回 = 200万粒子。種は `np.random.SeedSequence(20291750).spawn(1000)` から（B8とは別）。記録のあふれが0であること。
- 量: 深さ5 cmごとの6つの帯のそれぞれで、\|x\| ≤ 4 cm かつ \|y\| ≤ 4 cm の範囲の沈着を、線分の中点の位置で y > 0 と y < 0（および x > 0 と x < 0）に分け、`A = (E₊ − E₋)/(E₊ + E₋)` を作る（12個）。B8の領域（1 cm × 2 cm × 4 cm）の約60倍の体積を使うので、同じ粒子数でSEMは約1/8になる見込み。
- 誤差: 1,000回のそれぞれで E₊、E₋ を出し、比の誤差を回のばらつきから求める。
- **判定の規則（実行の前に固定）**: 12個すべてで |z| < 2.87（両側5%を12個で補正）なら「偏りは検出されない。B8の不合格は偶然のゆらぎと整合する」と記録する。1個でも |z| ≥ 2.87 なら「偏りがある」として、P3b-2に進まずに原因を調べる。どちらの場合も、B8の記録は不合格のまま残す。
- D1で偏りが検出されなかった場合、対称性は、P3b-3の試し計算（本番に近い粒子数）でもう一度、B8と同じ9個の対比で確かめる（そこでの規則はP3b-3の計画で固定する）。
- スクリプト: `prototypes/mv_electron/run_p3b1_diag.py`（Claudeが書く。診断の集計だけで、核には手を入れない）。結果は `docs/validation/mv/p3b/diag_symmetry.json`。

**速さの対処（別に行う）**: 領域の集計で、1歩ごとに配列を新しく作っている箇所と、15個の箱すべてに按分の計算をしている箇所を直す（結果の配列はバイト単位で変えない、を条件にする）。D1のあとに追補2として計画する。

**追補1の結果（2026-10-12）**: D1は「偏りは検出されない」。12個の最大は |z| = 1.61（限度2.87）。非対称の大きさは −0.53〜+0.75%、SEMは0.27〜0.48%。B8で外れた深さ10 cmのy方向にあたる帯は、5〜10 cmが +0.11 ± 0.29%、10〜15 cmが −0.53 ± 0.33%で、B8の −7.4% は再現しなかった。全沈着の重心は x = +0.003 ± 0.004 cm、y = +0.004 ± 0.004 cm。**偏りがないとすれば確率約1%の偶然が起きた、という説明と整合する。B8の記録は不合格のまま残す。**（上の「対比の精度が粗い」は不合格の原因ではない。限度2.77は偽の不合格が約5%になるように決めてあり、精度が粗いと検出できる偏りが大きくなるだけである。） 生データは `docs/validation/mv/p3b/diag_symmetry.json`。

# 計画: 路線2（kernel.pyのCUDA移植）の投資判断のためのスコープ・工数見積もり

- 状態: implemented
- 作成者: claude
- 実装担当: claude（本計画自体はコード変更を伴わない検討・文書化タスク）
- 日付: 2026-08-20
- 結果: [docs/gpu_speedup/route2_scoping/RESULTS.md](../../gpu_speedup/route2_scoping/RESULTS.md)

## 目的（1〜3行）

路線1（`docs/gpu_speedup/route1_mcgpu/RESULTS.md`）で「既存の完成品GPUコード(MC-GPU)」を
基準にGPUの速度天井（EGS5単スレッド比≈46倍・8並列比≈8倍）を実測した。この数字は
「ChatCarlo自身のCUDA移植がどこまで届くか」を保証しない。路線2（`kernel.py`のCUDA移植）
に着手する価値があるかを判断するため、実装に必要な工数・前提条件・リスクを見積もる。
**本計画はCUDA移植そのものを実装しない。** 見積もりを出し、着手可否の判断材料を揃えるまでがスコープ。

## 対象範囲

- 調査してよい: `chatcarlo/kernel.py`, `chatcarlo/tally_njit.py`, `chatcarlo/geometry.py`,
  `chatcarlo/detector.py`, `chatcarlo/transport.py`, `docs/plan_chatcarlo_speedup_post_egs5.md`,
  `docs/gpu_speedup/route1_mcgpu/RESULTS.md`, `docs/plan_scatter_correction_feasibility.md`
- 変更禁止: コード本体の変更（本計画は見積もりのみ。実装は別計画として承認を経てから）

## 受入条件（検証可能な形で列挙）

- [ ] `kernel.py`の現状制約（box限定・単色線源限定・parallel field限定・実効workers=1）を、
      実シーン（`examples/`配下5例）のうちどれが対応済み/未対応かを表で明示する
- [ ] CUDA移植に必要な作業を独立したサブタスクに分解する（少なくとも以下は個別に見積もる）:
      (a) cylinder/sphereジオメトリー対応, (b) 多色スペクトル対応,
      (c) heightfield対応（散乱線補正で必要）, (d) CUDAカーネルへの移植自体,
      (e) EGS5相互検証網の再実行（物理を変えないことの確認）
- [ ] 各サブタスクについて、既存の類似作業（Rayleigh/Compton重点サンプリング再設計、
      Phase3並列化、タリー精密化など）からの類推で規模感（小/中/大、または人日感）を出す
- [ ] 「路線2をやってもMC-GPU実測(≈70M hist/s)に届かない可能性がある」という懸念について、
      属人的な楽観/悲観ではなく、`kernel.py`の現在の実測スループットと
      MC-GPUのスループットの差の原因候補（言語・カーネル成熟度・物理モデルの違い等）を
      具体的に列挙する
- [ ] 散乱線補正プロジェクトとの接続に必要な追加要件（多色・heightfield）を明示し、
      「路線2をやれば散乱線補正が自動的に速くなるわけではない」ことを見積もりに反映する
- [ ] 最終的に「着手する/しない/条件付きで着手する」の判断基準を明文化する
      （例: 工数がXX人日以下なら着手、天井が結局Y倍未満ならROI不足、等）

## テストコマンド（実装完了の定義）

本計画はコード変更を伴わないため実行テストはなし。完了の定義は、上記受入条件を満たす
見積もりドキュメントが `docs/gpu_speedup/route2_scoping/RESULTS.md`（または同等の場所）
に書かれ、ユーザーが着手可否を判断できる状態になることとする。

## 実装方針

1. まず`kernel.py`の現状棚卸し（既にCLAUDE.mdとコード冒頭コメントに制約は書かれているが、
   実シーンとの対応表を作って可視化する）
2. 各拡張項目について、類似の過去作業（Rayleigh/Compton再設計＝物理モデル変更を伴う
   アルゴリズム置換の実例、Phase3並列化＝並列化实装の実例）を参照点として規模感を出す
   （ゼロから見積もるより、実績のある近い作業からの類推の方が精度が高いと判断）
3. GPU移植特有のリスク（RNGアルゴリズムの違いによる統計的検証の必要性、CUDA環境依存、
   Colab無料枠の制約下での開発サイクルの遅さ）を明示する
4. 「本当に速くなるか」の不確実性を隠さず、天井（route1実測）と下限（見積もりの前提が
   崩れた場合）の両方を示す

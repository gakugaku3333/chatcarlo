**参考：履歴をステップ数で並べ替える案**

**核を変えずに実装可能です。動的割り当てより単純な静的対照にもなります。**

順序配列 `order` を用意し、スレッドiが次を実行します。

```cpp
k = order[i];
p5b_history(t, seed, start + uint64_t(k), maxsteps, &L);
// 集計先は p5b_row(k,n)、履歴ごとの保存先は k
```

同程度のステップ数を隣接させれば、ワープ内の長短の差を小さくできます。元のkで乱数・行・保存先を決めれば、計算対象もバッチ所属も変わりません。順序配列が `[0,n)` の置換であることを検査します。

ただし、**実際のステップ数を得るには通常、一度輸送を完了する必要があります。** 保存済みCPU結果で並べ替える測定は、「実コストを知っている理想的な順序」の診断として有用ですが、新しい履歴への実用的な高速化とは分けて報告する必要があります。計測外でCPU輸送して得た順序を無料と扱うのは不適切です。

実用案としては、入射エネルギーなど安価に得られる量で予測して並べる方法があります。ただし、エネルギーだけでは最初に透過するかなどを予測できず、効果は測定事項です。短い履歴を早期判定するために輸送を途中実行して再開する案は、現行の凍結核の入口だけでは扱いにくく、別計画が適切です。

推奨する最小構成は、**静的割り当てのままの資源調整を先に比較し、動的割り当てを独立した候補にすること**です。各候補のGPU履歴出力をV0と直接照合し、選んだ構成で従来の鎖2を再実行すれば、速度目標を置かずに今回の問いへ答えられます。

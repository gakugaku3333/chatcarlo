## 目的

P5g の核は、表の定数（格子のエネルギーや表の値）の `log` を、呼ぶたびに計算し直している。これを**同じ端末の同じ `log` で最初に1回だけ計算した配列**から読む形に替え、各履歴の結果を P5g と**ビット単位で同じ**に保ったまま、倍精度の命令を減らす。速さは報告のみ（目標値なし）。あわせて、「時間を決めているのは倍精度の回路か」を確かめる材料にする。採否はユーザーが決める。

## 0. 前提事実（2026-10-16 に確認）

**倍精度の命令の内訳**（P5g、T4、10万履歴。`p5h/results/map/P5g_profile/source.csv` を手元で集計。`compiled.cu` の行）:
- 倍精度の命令（`DFMA`・`DADD`・`DMUL`・`DSETP`・`DMNMX`）はワープ命令の 29.7%（1.331e10 / 4.485e10）。
- 関数ごと: `quantities` 16.2%、`p5_table_rates` 12.4%、`p5_collision` 10.0%、`p5_gs_mu_cached` 8.3%、`p5g_charged` 7.1%、`p5_rotate` 6.9%、メラーの原始関数 7.8%。
- 対数の補間の7行で倍精度の命令の 30.6%。行ごとに「定数の `log` の数 ÷ その行の `log`・`exp` の数」を掛けて数えると、**定数の `log` は倍精度の命令の約 19.5%**（全ワープ命令の約 5.8%）。

**対象の行**（凍結ファイルの中。`log` の引数が表の定数だけで決まるもの）:

| 場所 | 式 | 先に計算する配列 |
|---|---|---|
| `p5a0_common.h:63`（`quantities`） | `log(e[i])`（2回）、`log(e[i+1])` | `log(brems_e)` |
| `p5a0_common.h:68〜70` | `log(v[5*i+k])`、`log(v[5*(i+1)+k])`（k=0,1,2） | `log(brems_v` の3列`)` |
| `p5_kernel.h:113`（`p5_table_rates`） | `log(e1/e0)` | 区間ごとの `log(e[i+1]/e[i])`（`e` は `rates` の1列目、または `ts`） |
| `p5_kernel.h:114〜115` | `log(rates[...])`（2列×2点） | `log(rates` の2・3列`)` |
| `p5_kernel.h:126`（`p5_gs_mu_cached`） | `log(t->ts[i+1]/t->ts[i])` | 区間ごとの `log(ts[i+1]/ts[i])` |
| `p5_kernel.h:66〜75`（`p5_log_interp`） | `log(es[...])`、`log(vs[...])` | `log(pes)`、`log(water` の列`)` |
| `p5_kernel.h:78〜95`（`p5_pair_value`・`p5_pair_interp`） | `log(es[...])`、`log(vs/q³)` | `log(pes)`、2つのしきい値ごとの `p5_pair_value(j)` |

- 変数を含む `log`（`log(t)`、`log(T/e0)`、`log(E)`、乱数の `log` など）は**替えない**。`log(T/e0)` を `log(T)-log(e0)` に書き換えるような、式の変形もしない（丸めが変わる）。
- **ビット一致の根拠**: `log` は同じ入力に同じ出力を返す決まった関数。同じ端末（CPU は `std::log`、GPU は NVRTC `--fmad=false` の `log`）で、同じ値（割り算 `e[i+1]/e[i]` も同じ IEEE の演算）を先に計算すれば、核の中で計算した値と同じビットになる。**手元で計算した対数を GPU に渡さない**（P5a0 で、端末と手元の `log` は最後のビットが違うことがあると分かっている）。GPU は核を起動する前に、端末の上で配列を作る。
- 凍結: `p5a0_common.h`・`p5_kernel.h`・`p5g_*`・`p5h_*` は変えない。

## 1. やり方（骨子）

- 新規 `p5i_*`。P5g の遷移の関数から上の対象の行に届く関数を、呼び出しの経路ごとに `p5i_` の名前でコピーし、**`log(定数)` の部分だけ**を先に計算した配列の読み出しに替える（P5h の §7 と同じ作り方。P5h の探索の変更は持ち込まない）。他の式は字句まで同じ。
- 先に計算する配列: CPU は駆動の初期化で `std::log` から、GPU は初期化の核で端末の `log` から作る。配列の作り方の式は、元の行の引数の式と字句まで同じにする（例: `log(t->ts[i+1]/t->ts[i])`）。

## 2. 関門（測る前に固定）

0. **配列の単体の検査**（CPU と T4 の両方）: 先に計算した配列の各要素が、同じ端末で元の式をその場で計算した値と、ビット単位で一致する。
1. **関門1**（手元、M3）: 新しい CPU ビルドが、保存済みの P5a Philox 100バッチとバイト一致。
2. **関門2**（T4）: 指定の2万履歴で、履歴ごとの全出力が P5g と `core.bits` で一致。
3. **関門3**（T4）: P5c の C0〜C4（1,000万履歴）。数値の基準は P5b 計画 §3 のまま。関門3の指紋に `nspec=20` を入れる（P5h の修正1の教訓）。
- **速さ**（報告のみ）: 同じセッションで P5g と P5i を交互に3回ずつ（P5h と同じ方法）。
- **地図**（報告のみ）: P5g と P5i の両方で ncu の生の記録（`.ncu-rep` と `source.csv`）を取る。CSV の読み取りが失敗しても、**次の構成の記録を取り続ける**（P5h では P5g の読み取りで止まり、P5h の記録が取れなかった）。集計は Claude が手元で行う。倍精度の命令の数が P5g より減ったことを見る。
- 判定の記録の指紋は計算のファイルだけ。Colab は「すべてのセルを実行」1回で済む形にする（ソースは Drive の zip から、P5h と同じ）。

## 3. 範囲

- 新規のみ: `p5i_*`（核のヘッダー、CPU と GPU の駆動、Python の判定、Colab のスクリプトとノートブック）、`tests/test_p5i.py`、結果の文書。
- 変更禁止: 凍結した核、P5a〜P5f-0 のファイル、`p5g_*`、`p5h_*`。
- スコープ外: 変数を含む `log`・`exp` の変更、式の変形、単精度化、探索の変更、事象ごとのキュー（候補2）、物理の変更。

## 4. 停止条件

- 関門0か1で1つでも不一致 → GPU に進まない。原因を調べて報告。
- 関門2・3のどれかが不合格 → 採用しない。P5g のまま。
- 速さが P5g より遅い、または差が3回の幅の中 → そのまま報告し、ユーザーが決める。

## 5. 期待の幅（単純化した仮定による試算。上限ではない。判定に使わない）

定数の `log` が倍精度の命令の約 19.5% を占める。時間が倍精度の回路だけで決まるという仮定での試算は ×1.24（= 1/(1−0.195)）、命令の数で決まるなら ×1.06（= 1/(1−0.058)）。P5h では、命令の数の見込みが外れた（×1.136〜1.255 の見込みに対し、実際は 0.985）。

## 6. 詳細（1巡目の反映。§1〜§5 と食い違うときは本節が優先）

**一致の主張の範囲（指摘1）**: 一致は「固定した構成の中で、元の経路の計算と先に計算した値が同じ」に限って述べる。構成は (a) M3・clang++（関門1の指定、`-ffp-contract=off`）、(b) T4・NVRTC（`--fmad=false`、CUDA と NVRTC の版を記録）。clang と g++、CPU と GPU の間の一致は求めない。初期化は、核と**同じ翻訳単位・同じコンパイルの指定**で行う（CPU は同じ `.cpp`、GPU は同じ NVRTC のソースの中の初期化の核）。

**関門0の具体化（指摘2・5）**: 配列の自己比較では足りないので、次の2段にする。
- (i) 要素の比較: 先に計算した各要素を、**凍結した元の関数を呼ぶ検査の経路**で得た値と比べる。割り算を含むものは、商と、対生成の `q`・`(q*q)*q`・対数の引数のビットも記録して比べる。
- (ii) 関数の出力の比較: 凍結した元の関数（`quantities`・`p5_table_rates`・`p5_gs_mu_cached`・`p5_log_interp`・`p5_pair_interp`・`p5_coefficients`）と新しい関数に同じ入力を与え、すべての出力（戻り値・出力の引数・添え字）がビット単位で同じかを比べる。入力は、各格子点、その `nextafter` の両隣、範囲の外、しきい値の両隣、`quantities` の `i==0` の区間、対数を取ると同じ値になる隣の格子、各区間の中の乱数 1,000 個ずつ（`gs_mu` は K と乱数の組も）。
- 置き換えた場所ごとに、検査の件数と、通常の輸送で通った回数（検査のビルドの数え上げ）を記録する。通った回数が 0 の場所があれば止める。
- 順番: CPU の関門0 → 関門1 → T4 の関門0 → 関門2 → 関門3。T4 の関門0が不合格なら輸送の計算に進まない（指摘8）。

**配列の仕様（指摘3・4）**: 配列ごとに、元の配列・列・stride・長さ・有効な添え字の範囲を表にして、実装の文書に書く。
- `p5_table_rates` は `ratecols==3`（格子は `rates` の1列目、値は2・3列目）と、それ以外（格子は `ts`、値は `shift=0` から）の両方を元と同じ分岐で扱う。今の入力は `ratecols==3`（480×3）だが、もう一方の分岐も関門0の (ii) で検査する。
- 区間の配列（`log(e[i+1]/e[i])`）は長さが格子の数−1。
- 対生成は、しきい値と値の列の組（`water+3` と `thresholds[0]`、`water+4` と `thresholds[1]`）ごとに別の配列。
- 元の添え字の順を保ち、同じ値の重複を消したり並べ替えたりしない。
- **元が評価しない場所は計算しない**: `quantities` の `i==0` で使われない値、しきい値以下の行の `p5_pair_value` などは計算せず、NaN の番兵を入れる（検査で、番兵を読んだら止める）。元が実際に評価する場所に 0 や負の値があれば、補正せず、元と同じく `log` をそのまま計算する（今の入力にあるかは初期化で数えて記録する）。

**対象の範囲（指摘6）**: 今回の対象は**補間の表の対数**（§0 の表）だけ。`p5_shape` の `Z[j]` の対数（`p5_kernel.h:233〜234`）、`log(.01)` などの定数、メラーの原始関数の `.5` の呼び出しは除外する（補間の表ではなく、呼ばれる回数も少ない。次の候補にする）。

**地図（指摘7）**: P5h の `divergence_map` の仕組み（行の情報のありとなしで、履歴の出力・SASS・資源を比べる）を引き継ぐ。測る核は名前で固定し（初期化の核を測らない）、履歴の数・seed・start・ウォームアップ・測る起動を固定する。構成ごとに、取得・書き出し・読み取りの状態を別に記録し、**一方が失敗しても、もう一方の取得を試す**。地図の記録には、計算のソース・入力と作った配列のハッシュ・指定・環境を残す。集計の結論（倍精度の命令の数）は Claude が手元で出す。

**初期化（指摘9）**: 「最初に1回」は、入力の表・端末・ビルドの構成ごとに1回。表を変えたら作り直す。GPU は輸送の核の前に同じストリームで初期化の核を動かし、配列は GPU のオブジェクトの寿命の間だけ持つ。速さの報告は、輸送の核の時間と、初期化の時間・追加のメモリを分けて出す。

**ファイルとテスト**: 新規 `prototypes/mv_electron/gpu/p5i_kernel.h`（P5g の遷移の関数から対象の行に届く関数を `p5i_` の名前でコピーし、`log(定数)` の部分だけを配列の読み出しに替える。他の式は字句まで同じ）、`p5i_logs.h`（初期化。CPU/GPU 共通）、`p5i_cpu.cpp`、`p5i_gpu.cu`（初期化・本番・履歴ごと・検査・関門0の核）、`p5i_core.py`（指紋と判定。指紋に `nspec=20` を含む）、`p5i.py`（手元の関門0・1）、`p5i_colab.py`・`p5i_colab.ipynb`（関門0〜3・速さ・地図を「すべてのセルを実行」1回で。ソースは Drive の zip）、`prototypes/mv_electron/tests/test_p5i.py`。テストには、P5i の CPU の経路に、置き換えた元の `log(定数)` の式が残っていないことの検査と、n=2,000 の P5g との一致を含める。

## 7. 2巡目の反映（§6 と食い違うときは本節が優先）

- **関門0の正式な条件**（指摘A）: 凍結した元の関数と新しい関数の**出力の比較**（§6 の (ii)）を正式な条件にする。§6 の (i)（要素・商・`q`・対数の引数の比較）は、凍結した関数の中の値を外へ出せないため、検査の経路で元の式を再び書いて計算する**補助の診断**とし、合否には使わない（不一致の原因を調べる材料として記録する）。
- **到達の数え上げ**（指摘B）: 関門0では、単体の検査で各場所を通った件数を判定する。通常の輸送で各場所を通った回数は、関門1（CPU、検査のビルド）と関門2（T4、検査のビルド）で判定し、0 の場所があれば不合格。検査のビルドの出力も、通常のビルドと同じく P5g とのビット一致を関門1・2に含める。
- **最終の報告**（指摘C）: 全体の倍精度の命令の数・全命令の数・レジスタとローカルメモリ・輸送の時間・初期化の時間を、P5g と P5i で並べる。命令の数が減ったことだけで「倍精度の回路で時間が決まる」とは結論しない（速さが変わったかどうかと合わせて述べ、解釈は仮説として書く）。

## 1. P4b: 無限の水での衝突カーマの総和

### 1-1. 関係

無限の水の中に光子を1個置き、すべての世代の光子（散乱、制動放射、消滅）を追う。エネルギーは最後にすべて水に沈着する。各世代の光子の衝突カーマは「その光子が作った荷電粒子が、放射で失う分を除いて、水に渡すエネルギー」なので、すべての光子の衝突カーマの総和は、入射エネルギーに等しくなるはずである。

`ρ_col = Σ(collision_kerma) / Σ(入射エネルギー)` の期待値は `1 − f_cut`。（置き換え済み: 末尾の「詳細レビューの反映」1を参照）`f_cut` は10 keV未満になってその場に沈着した光子のエネルギーの割合（核はこれを別に集計していないので、補正はしない。期待される大きさは1節末の見積もり）。

これが1からずれる原因は、(a) NISTの μen/ρ が織り込んでいる放射の割合 g（制動放射、飛行中の消滅）と、試作が事象として起こす放射損失の違い、(b) NISTの μtr と試作の係数（XCOM由来）の違い、(c) 核の誤り。NISTの μen/ρ は輸送に使っていないので、EGS5によらない検査になる（ただし断面積と放射阻止能の出典には共通の部分があり、完全に独立な物理モデルではない）。

同じ計算で、試作自身の係数による全カーマの総和 `ρ_tr = Σ(kerma)/Σ(入射)` も出る。こちらは1より大きくなる（放射で失われて再び光子になる分を何度も数えるため）。`ρ_tr − ρ_col` は「放射で光子に戻ったエネルギーの割合」に相当する。報告のみ。

### 1-2. 計算（固定）

- 核: `photon_transport_p3b.run_coupled(E, n, seed, .05, .025, 2000., *run_p3s.inputs('elsepa'), **run_p3s.rule_kwargs('own'), annihilate_in_flight=True, brems_mode=2, score_kerma=True, score_pair=False, source_state=光子(z=1000, 向き+z, エネルギーE))`。`source_state` は `photon_state(E,1000.,0.,0.,1.,0)` と同じ23要素の配列。
- エネルギー: 単色 0.5、1.25、2、6、10 MeV。各10万履歴。種 `20291790 + 番号(0〜4)`。（置き換え済み: 粒子数は「詳細レビューの反映」2のとおり試し計算から決める）
- 判定する量 B1（5個）: 100バッチそれぞれで `r_b = Σ_z collision_kerma[b] / (バッチの入射エネルギー) − 1`（バッチの入射は `(n/100)×E`）。`mean(r_b)` が差、`std(r_b, ddof=1)/10` がSEM。
- **判定**: |差| ≤ 1%、かつ SEM ≤ 0.1%。SEMが超えたら「統計不足」（追加の計算はしない）。許容1%の根拠: この試作の他の判定と同じ水準。NISTの表の不確かさと g のモデルの違いを分けて評価できるだけの文献値を持っていないので、これより細かい許容は置かない。
- 健全性: `totals` の流出が入射の 1e-6 以下（厚さ2,000 cmで足りていること）、`violations` 0、打ち切り0。満たさなければ「判定できない」。
- `f_cut` は事前に値を置かず、補正もしない。（置き換え済み: 書き方は「詳細レビューの反映」1のとおり）結果の文書では、差の符号と大きさが `f_cut`（負の方向に働く）と整合するかを述べるだけにする。

### 1-3. 報告のみ

- `ρ_tr`（5エネルギー）と `ρ_tr − ρ_col`。
- **B2 深さごとの 線量÷衝突カーマ**: Mohanの10 MVスペクトル、平行な広いビーム、厚さ30 cmの平板（P3rの本番と同じ設定に `score_kerma=True` を足したもの）、200万履歴、種 `20291796`。深さ 5〜10、10〜15、15〜20、20〜25、25〜30 cm のブロックで `Σ沈着(fine) / Σcollision_kerma` と、そのSEM（バッチごとの比から）。あわせて 0〜5 cm も出す。「1をわずかに上回り、ほぼ一定」は過渡的な荷電粒子平衡が成り立つ場合の仮説であって、判定しない（骨子2節）。スペクトルの読み込みは `batch_kernels_p3u.spectrum({'spectrum':'mohan',…})` と同じ既存の関数を使い、値を出力に写さない。この `.npz` は追跡しない。

## 2. P4c: 連続減速の飛程

### 2-1. 2段の比較

- **C1 刻みの積み上げ**: 核（P1の電子の核、硬衝突なし・散乱なし・直進）で電子が止まる深さ と、同じ阻止能の式 `physics.stopping(T, False)` の数値積分 `R_int(T0) = ∫_{CUT}^{T0} dT/S(T)` の差。
- **C2 阻止能と補間**: `R_int(T0)` と、ESTARの表の `R_ESTAR(T0) − R_ESTAR(0.01 MeV)` の差。

### 2-2. C1 の方法（核の出力だけを使う）

電子は直進するので、厚さ `L` の平板に垂直に入れると、止まる深さ（飛程）が `L` より大きい履歴だけが後ろの面から出る（`ledger[h,2] > 0`）。

- `L_j = R_int × (1 + x_j)`、`x_j = −0.0100, −0.0095, …, +0.0100`（41点、0.05%刻み）。各 `L_j` で `transport.run(T0, 2000, seed, .05, K, np.array([0., L_j]), L_j, *gs, scoring=False, hard_on=False, mode=2)` を動かし、透過した履歴の割合 `p_j` を得る。`*gs` は `ts,ks,us,ys`（`run_p3s.inputs('elsepa')` の先頭4つ。`mode=2` では散乱の表は使われないが、引数として要る）。`K` は 0.025。種は `20291800 + 100×(エネルギーの番号) + j`。
- 平均の飛程（相対）: `x̄ = x_0 + Σ_j p_j × 0.0005 − 0.00025`（`p` を `x` で積分した値。`p_0 = 1`、`p_40 = 0` であることを確かめる。満たさなければ「判定できない」）。SEMは、41点の二項分布の分散の和から: `0.0005 × sqrt(Σ p_j(1−p_j)/2000)`。
- エネルギー: 0.1、1、10 MeV。
- **判定 C1**: |x̄| ≤ 0.1%、かつ SEM ≤ 0.1%/3。
- 数値積分 `R_int`: `u = ln T` で等間隔の20,001点の台形則。点数を2倍にして相対変化が 1e-6 以下であることを確かめる。

P1の核を使う理由と限界: 硬衝突を切れるのがこの核だけである。エネルギーのヒンジの更新（`energy_init` と同じ式）は、その後の核（P3b、P4）にそのまま引き継がれている。ただし「いまの核のループそのもの」を動かした検査ではない。結果にそう書く。

### 2-3. C2 の方法

- `run_p4bc.py fetch`: ESTARの既定のエネルギーの表（飛程の列つき）を取得し、応答をそのまま `docs/validation/mv/p4/estar_range_water.html` に保存する。URLと送る項目、取得日、sha256 を `checks_p4bc.json` に記録する。取得のしかたは実装時に `fetch_data.py` とESTARのページを見て決め、任意のエネルギーだけを指定する方法（飛程が返らない）は使わない。取得できなければ C2 は「未実施」とし、理由を書く（C1とP4bは行う）。
- 表から 0.01、0.1、1、10 MeV の飛程 [g/cm²] を読む（表にその点があること。無ければ対数補間せず「未実施」）。
- **判定 C2**: `R_int(T0) / (R_ESTAR(T0) − R_ESTAR(0.01)) − 1` の絶対値 ≤ 0.1%。統計はない。
- 0.1%の根拠: P1 K1 で阻止能の節点での一致が最大0.049%だった。補間の誤差が加わるので、超えた場合は不合格として記録し、原因（補間・密度効果の表・放射阻止能）を考察する。許容は変えない。

## 詳細レビューの反映（本文と食い違う場合は、この節が優先する）

1. **B1の期待値の説明**: 関係は期待値として成り立つ（履歴ごとの恒等式ではない）。`ρ_col` の期待値は概念的に `1 − f(10 keV未満の光子の局所沈着) − f(10 keV未満の制動放射を連続損失として沈着した分) + Δ(カットオフ・モデル・表の違い)`。Δには、電子・陽電子を10 keVで止める扱い、原子の緩和を扱わないこと、束縛のないCompton、陽電子に電子の物理を使うこと、NISTの g が含む蛍光・損失の揺らぎ・ノックオンの効果が入る。差を1つの原因に帰さない。結果の文書では「10 keV未満の光子は負の方向に寄与するが、寄与の大きさは分離していない」と書く。連続の制動放射の割合は `(brems[8] − brems[1]) / 入射` として報告する（Codexの概算では入射の0.014〜0.018%程度）。本文42行の「1節末の見積もり」は無い（削除扱い）。
2. **B1の粒子数**（本文の「各10万履歴」を置き換える）: 最初の飛跡だけで SEM ≥ (μen/μ)/√N という下限があり、10万履歴では0.11〜0.22%で条件（0.1%）に届かない。試し計算（各10万履歴、種 `20291790 + 番号`）のSEMから `N_need = 100000 × (SEM/0.1%)²` を求め、1.5倍して10万の倍数に切り上げる（最低10万）。本番の種は `20291810 + 番号`。1条件で500万履歴を超える場合は本番に進まずユーザーに相談する。試し計算の値は判定に使わない（表には載せる）。粒子数は `checks_p4bc.json` の `lock` に、ソースのハッシュと一緒に書き、本番はそれが一致するときだけ動く。入口は `run` を `run`（C1・C2・B1の試し計算・鍵）と `production`（B1の本番・B2）に分ける。
3. **保存**: B1は、核の出力を受け取ったらすぐに深さ方向を合計し、バッチごとの `kerma`・`collision_kerma` の総和（各100個）、`totals`・`violations`・`counts`・`brems`・`maxima` だけを保存する（核の出力1回分は約184 MB）。
4. **健全性の具体化**: B1・B2: `totals[0] == n×E`（B2はスペクトルなので除く）、流出 ≤ 入射の1e-6（B1のみ）、`violations` すべて0、`counts[5:7]` 0、使う配列がすべて有限、分母が正。C1（各厚さ）: `counts[5:7]` 0、`ledger[:,4:6]` すべて0、`|ledger[:,3]|` ≤ `T0×1e-9`、`counts[1:3]` 0（散乱・硬衝突の事象なし）、`ledger[:,1]`（後方の流出）すべて0、値がすべて有限。満たさない条件は「判定できない」。
5. **試験の追加**: `totals[0]==n×E`、カーマの2配列の形・有限・正。同じ種でカーマの採点の有無を変えて `totals`・`counts` が一致。総和の比の規格化を合成配列で確認。C1で `p_40≠0`・非有限・失敗した履歴があるときに「判定できない」。保存してから読み直した結果と連続して計算した結果が一致。
6. **B3は行わない**: 骨子のB3（相互作用の点での運動エネルギーの加算との一致）は、核に手を入れないこの設計では行えない。B1の合格を、B3を確かめたという意味で報告しない。`ρ_tr − ρ_col` は「試作の μtr とNISTの μen の差の飛跡積分」であって、直接数えた放射エネルギーではない、と書く。
7. **B2の核を明記**: `photon_transport_p3b.run_coupled(10., 2000000, 20291796, .05, .025, 30., *run_p3s.inputs('elsepa'), **run_p3s.rule_kwargs('own'), annihilate_in_flight=True, brems_mode=2, score_kerma=True, score_pair=False, spectrum_edges=edges, spectrum_cum=cum)`（照射野・領域なし）。`edges, cum = batch_kernels_p3u.spectrum(dict(spectrum='mohan'))` 相当（実際の引数の形は既存の関数を読んで合わせる）。保存は `fine`・`collision_kerma`・`kerma` のバッチ×深さと `totals`・`violations`・`counts`。スペクトルのファイルのハッシュ（`run_p3a.SPECTRUM_SHA`）を設定に入れる。

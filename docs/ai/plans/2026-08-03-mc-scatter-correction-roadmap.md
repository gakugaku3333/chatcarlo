## 目的

グリッドなしで撮影した診断X線2次元画像の各ピクセルについて、一次線成分と散乱線成分を
Monte Carloで推定し、散乱線成分を差し引いて「グリッドあり相当」の画像を得る仕組みを
ChatCarlo上に構築する。市販のFUJIFILM Virtual Gridが体厚マップ＋STPRカーネル法で
実現している処理を、患者個別のMC物理計算で置き換えることによる精度向上と、
統計不確かさの定量化を狙う。

## 全体アーキテクチャ（Phase間で共有する前提）

補正の全体フローは以下。Phase分割はこのフローの依存関係に従う。

```
観測画像 I_obs(x,y)
  → [A] 厚さ逆算: Beer-Lambert逆問題で水等価厚マップ t(x,y)
  → [B] 3Dモデル構築: t(x,y) を検出器面に垂直押し出し（2.5D heightfield）
  → [C] MC実行: 検出器タリーで一次線像 P_mc と散乱線像 S_mc を弁別集計
  → [D] 減算: I_corr = I_obs − S_scaled（S_mcを観測スケールへ正規化）
  → [A]へ反復（散乱混入による厚さ過小評価の補償、1〜2回）
  → [E] グリッド効果模擬（任意）・ノイズ低減（別軸）
```

**[C]がすべての土台**であり、[C]がなければ[A][B][D]の正しさを検証する手段がない。
したがってPhase 0は[C]単独の実装と検証に限定する。

## Phase 0: 検出器タリー（最初の実装単位）

### やること

有限矩形の**終端型 `DetectorPlane`** を定義し、到達した光子を一次線/散乱線を弁別して
ピクセル毎に集計するタリーを実装する。`chatcarlo/tally.py` の `VoxelGrid` が輸送
ジオメトリと独立した「スコアリング専用の格子」であるのと同じ思想の、2D版。

### なぜこれが最初か

- 散乱補正アルゴリズム全体の**唯一の観測窓**であり、これ無しでは他の全Phaseが検証不能。
- 既存の輸送ループに素直に乗る。各飛行区間の始点 `o` / 終点 `ends` /
  相互作用前エネルギー `e` が同時に手に入る箇所（`transport.py` の `ds`/`ends` 計算直後）で、
  線分と平面の解析交差を判定して加算できる。解析的サーフェストラッキングとの相性は良い。
- 単体で意味のある検証ができる（下記STPR再現）。

### 設計上の判断（Codexレビューで確定した論点を含む）

1. **「面通過」ではなく「検出」を数える。終端型にする。**（Codexレビュー指摘1、採用）
   単純な surface-crossing tally にすると、1つの光子が散乱後に同じ面を複数回横切って
   多重計上され、実在する吸収型検出器の信号にならない。以下に固定する:
   - 有限矩形の `DetectorPlane` を定義する
   - **法線方向への正の交差だけ**を受理する（後方交差は除外）
   - 各historyの**最初の受理交差だけ**を記録する
   - 記録後はその光子を **detected 終端**として輸送を停止する

   Phase 0の検出器は「理想的に100%吸収する面」と明示する（吸収効率・DQEは後段Phase）。

   **輸送ループへの組み込み順序を固定する**（Codexレビュー2回目の指摘2、採用。
   実コードで検証済み。「`ds`/`ends` 計算直後に加算」だけでは不十分だった）:
   1. `t_detector` を算出し、受理交差なら **`ds = min(ds, t_detector)` に区間を短縮する**
   2. **短縮後の `ds` だけ**をgridへtrack-length積算する
      （短縮前の `ds` を入れると検出器の背後までカーマを積算してしまう）
   3. 検出なら `detected=True` / `alive=False` とし、**`tau` は消費も更新もしない**
   4. 相互作用・境界越え・`tau -= mu*t_boundary`・境界epsilon移動は**実行しない**
   5. `t_detector == ds`（材料境界または相互作用点と一致）の**タイの優先規約**を固定する:
      **受理検出器を優先し `t_detector <= ds` で検出とする**

   **世界境界との関係を明示する**（Codexレビュー2回目の指摘1、採用）:
   現行 `Geometry` の世界境界は物体bbox＋50 cmで決まり、輸送はその境界を先に
   `escaped` として終端する。**したがって物体から50 cm以上離れた実用的なSIDの
   検出器面は、検出される前に脱出してしまう**。子計画では
   「DetectorPlaneを世界bboxの構成要素に含める」（推奨）か
   「検出器全域が世界bbox内にあることをscene検証で必須にする」のどちらかを固定し、
   **「検出器が世界境界の直前・直後にある」受入テストを必ず置く**。
   **物理的な含意を明記する**: 終端型にすると検出器背後からの後方散乱が輸送されなくなる。
   実機では検出器・寝台からの後方散乱が被写体へ戻るため、これは近似である。
   Phase 0のスコープでは検出器に到達する信号だけが関心事なので許容するが、
   **この近似は子計画に明記し、後段で影響を評価できる状態にしておく**。

2. **`escaped` とは排反な `detected` 終端を新設する。**（Codexレビュー指摘2、採用）
   現行 `BatchResult.escaped` は世界境界に達した場合だけ `True`
   （`transport.py` の `esc_now` 参照）。検出器で停止させるなら `detected` を
   独立の終端事象として追加し、吸収・検出・世界脱出を**排反**にする必要がある。
   これに伴い、当初書いていた「検出器通過エネルギーと既存の吸収/脱出集計の突合」という
   受入条件は**そのままでは成立しない**（面通過は脱出の部分集合であって排反な収支ではない）。
   正しい恒等式に置き換える:

   ```
   入射エネルギー = 物質への沈着 + 検出器到達エネルギー + 世界境界からの未検出脱出エネルギー
   ```

3. **`n_scatter` は「散乱次数」ではなく「相互作用回数」である。**（Codexレビュー指摘3、採用）
   実コードで確認済み: `transport.py` の光電吸収分岐でも `n_scatter[photo_idx] += 1` が
   実行される。したがって:
   - **二値分類は正しい**: primary = `n_scatter == 0` / non-primary = `n_scatter >= 1`
     （K蛍光を放出して飛び続ける光子も non-primary。これは意図どおり）
   - **「1次散乱／多重散乱」の内訳を出すには別カウンタが要る**:
     Compton/Rayleigh の回数 `n_compton_rayleigh` を独立に追跡し、
     蛍光由来は**独立カテゴリ**として分ける。当初計画の「n_scatterで散乱次数別」は誤り。
   - タリーのカテゴリは最低限: `primary` / `single_scatter` / `multiple_scatter` /
     `fluorescence_secondary` の4分とし、**合計が total と一致することをテストで固定する**。
   - **排反分類の真理値表を子計画で先に定義する**（Codexレビュー2回目の指摘4、採用）。
     蛍光光子がさらにCompton/Rayleighを起こす場合、Compton後に光電吸収して蛍光放出する
     場合をどのカテゴリに置くかが未定義のままでは実装できない。historyごとの
     `had_fluorescence`（bool）と `n_compton_rayleigh`（int）の2変数に基づく排反規約
     （例:「`had_fluorescence` が真なら常に `fluorescence_secondary` を優先、
     それ以外で `n_compton_rayleigh` が 0 / 1 / 2以上」）を**表として書き下してから**
     実装する。**合計一致のテストだけでは誤った分類でも通ってしまう**ので、
     真理値表の各行に対応するテストを置くこと。

4. **保存量は面積正規化したエネルギーフルエンス `ΣE / pixel_area` とする。**
   （Codexレビュー指摘4、採用）ピクセル和のままだとピクセルサイズを変えると値が変わり、
   再ビニングで保存しない。energy-integrating検出器の応答（吸収効率×E）は
   後段Phaseで重み関数として掛ける。

5. **単一の細密グリッドに集計し、粗い散乱像は輸送後に決定論的に再ビニングする。**
   （Codexレビューの代替案、**採用**）当初計画は「一次線像と散乱線像で独立解像度の
   タリーを同時に持つ」としていたが、平面タリーの輸送時コストは交差1回＋整数除算で
   ボクセルDDAと違って極めて安い。散乱ビンを粗くしても輸送コストはほとんど下がらず、
   変わるのは配列メモリと後処理だけなので、二重ビン化は複雑さに見合わない。
   細密グリッド1本＋面積保存的な後処理（粗化・平滑化・一次ピクセルへの再配分）にする。

   **ただし1点だけ補足する（Claudeによる追加、代替案の適用範囲の限界）**:
   粗ビンの**統計不確かさ**は細ビンのRから事後合成できない（和の分散は分散の和ではなく、
   細ビン間の相関項が要る）。
   **この主張はCodexが実コードで検証し正しいと確認された**（2回目レビュー指摘3）:
   完全相関した2つの細ビンで、正しい粗ビンR = 0.5773502692 に対し、細ビンの `Q` を
   単純加算して求めた誤った粗ビンR = 0.0 になる。

   **対処の記述はCodexの指摘に従って精密化する**（初版の「粗解像度のモーメント配列を
   輸送中に別途積算する」は曖昧だった）。十分なのは、各カテゴリ・各粗ビンについて
   **バッチごとの粗ビン寄与和**を得て、バッチ終了時に
   `Q_coarse += delta_coarse**2 / n_histories_in_batch` を積む場合である
   （既存 `tally.py` のsnapshot-diff方式と同じ形）。**輸送中に細ビンの `Q` を
   粗く加算するのでは不正確**。粗タリー側にも `T` / `Q` / `prev` / `n_batches` /
   `n_histories` を持たせることを子計画で固定する。
   （代替として細ビンの各バッチ寄与を全バッチ分保存すれば事後合成も可能だが、
   現設計にそのデータはなくメモリも重い。採らない。）

   子計画では「Phase 0で粗ビンのRを出すか、Phase 2まで先送りするか」を明示的に決める。

6. **統計機構は既存ロジックを「共通化」する。「再利用」ではない。**
   （Codexレビュー指摘6、採用）`VoxelGrid.end_batch` は `kerma_keV` と
   `h10_track_pSv_cm3` の2配列に固定されており、`ScalarMoments` は材料名キーの
   スカラー辞書用なので、**どちらもDetectorTallyへそのままは流用できない**。
   正しい方針は、snapshot-diff方式と `(T, Q, M, N)` の推定式を**共通の配列モーメント
   ヘルパーとして抽出**し、`VoxelGrid` と新 `DetectorTally` の両方がそれを使うこと。
   既存の推定器を作り直すのではなく、既存ロジックを括り出す。
   絶対制約はVoxelGridと同じ:「統計ON/OFFでtotalがビット一致」。

7. **【重要な訂正】MC統計誤差Rと量子ノイズは別物である。混同しない。**
   （Codexレビュー指摘7、採用。`docs/plan_scatter_correction_feasibility.md` の
   補足検討節にあった「既存のbatch統計R機構がほぼそのまま使える」という記述は
   **不正確だったので訂正する**）
   - **MC推定誤差（既存のR）**: MC推定平均の不確かさ。history数を増やせばゼロに近づく。
   - **物理的な量子ノイズ予測**: 実撮影の光子数に依存して**残る**量。
     検出scoreの1次・2次モーメントを**実光子数（mAs校正）へスケールして**得る別量。

   この2つを同じ「分散マップ」として扱ってはならない。Phase 0では両者を
   **別の出力として分離して持つ**ことを受入条件にする。

8. **エンジン**: numpy経路（`transport.py`）で実装する。kernel経路（`kernel.py`）への
   対応はPhase 0のスコープ外（kernelはbox/単色/parallel限定でまだ実シーンに使えない）。

### 受入条件の骨子（子計画で数値を事前登録する）

- [ ] **解析解との照合（一次線）**: 単一材料スラブ・平行ビーム・単色で、
      一次線像の各ピクセルが Beer-Lambert `exp(-μt)` と統計誤差内で一致すること。
- [ ] **エネルギー収支の恒等式**（上記2の形）が、蛍光あり/なし・一次/非一次別に
      成り立つこと。**要素単位で確認する**（合計だけの一致で済ませない）。
      **測り方を子計画で定義する**（Codexレビュー2回目の指摘5、採用）: 既存の材料別
      沈着はバッチ全体の材料別辞書であり、history別でもカテゴリ別でもない一方、
      検出・未検出脱出エネルギーはhistory終端に属する。そのため恒等式の検証には
      **少なくともテスト用に**history別の「全衝突沈着」「検出終端エネルギー」
      「未検出脱出終端エネルギー」を保持する必要がある。
      **収支に使うのは衝突沈着であって、gridのtrack-lengthカーマではない**
      （この2つは別の推定量。混ぜると収支が合わない）。
- [ ] **終端の排反性の直接検査**: 各historyで `absorbed` / `detected` /
      `escaped`（未検出脱出）のちょうど1つだけが真であることをテストで確認する。
- [ ] **カテゴリの完全性**: `primary + single + multiple + fluorescence == total`
      がビット一致で成り立つこと。
- [ ] **幾何・ビン規約の境界条件テスト**（Codexレビュー指摘5、採用）:
      検出器中心・ピクセル境界・外周・角を通る光子のビン規約（半開区間）、
      面上を走る光子、始点/相互作用点が面上にある光子、後方交差の除外、
      斜入射、有限検出器外への逸脱、無物体・単色・平行ビームで指定ピクセルだけが
      一様に加算されること、発散ビームで既知の幾何学的投影とピクセル位置が一致すること。
      **Beer-Lambertの平行ビーム試験だけでは座標投影・ピクセル割当・有限面・斜入射の
      誤りを検出できない**ため、これらは独立に要る。
- [ ] **既存輸送への非侵襲性**: 検出器を渡さない場合、既存の輸送結果が
      同一seedでビット一致すること。
- [ ] **輸送区間短縮の検証**（Codexレビュー2回目の指摘2に対応）:
      検出器面が飛行区間の途中にある条件で、(a) gridへの総track lengthが
      **検出器までで止まる**こと、(b) 検出により `tau` 残量を使った次ステップや
      相互作用が**起きない**こと、(c) 材料境界・相互作用点と検出器面が
      **同一距離になるタイ**が規約どおり一意に処理されること。
- [ ] **API・並列・kernelの境界**（Codexレビュー2回目の指摘6、採用）:
      DetectorPlaneは `transport_photons` だけでなく `_run_batches`・並列worker・
      親側集約まで通す必要がある。serial/parallelでのタリー集約、同一 `(seed, workers)`
      での再現性、workers数を変えた場合の統計的同等性を確認すること。
      さらに **`engine="kernel"` とDetectorPlaneの併用は明示的にエラーにする**
      （黙って検出器指定を無視する経路を将来に残さない）。
- [ ] **STPR vs 厚さ曲線の再現**: 水スラブの厚さを 0〜30 cm で振り、
      60/80/100/120 kV で STPR（散乱/一次）を計算し、
      **単調増加・kV依存の順序・厚さ20cmでのオーダー**がFUJIFILM技報Fig.3および
      公開文献値と整合すること。**合格閾値は子計画で事前登録し、後から動かさない。**
      技報Fig.3は図からの目視読み取りなので、点一致ではなく形状・オーダーでの判定とし、
      **この読み取り精度の限界を子計画に明記する**。
- [ ] **散乱内訳の妥当性**: 薄いスラブでは単一散乱が支配的、厚いスラブでは
      多重散乱の割合が増える、という定性挙動が出ること。
- [ ] **統計ON/OFFでのビット一致**（既存タリーと同じ絶対制約）。
- [ ] **MC統計誤差と量子ノイズ予測が別出力として分離されていること**（上記7）。
- [ ] **ミューテーションによる検出力確認**: 少なくとも「primary/scatterの弁別条件を
      反転する」「ピクセル割り当てを1ピクセルずらす」「後方交差の除外を外す」の
      3つの変異でテストが実際に落ちることを確認する
      （Phase 1/2の教訓、`2026-08-01-kernel-*` 参照）。

### スコープ外（Phase 0でやらないこと）

- 厚さ逆算・3Dモデル構築・減算（Phase 1b以降）
- heightfieldプリミティブ（Phase 1a）
- 検出器応答モデル（吸収効率・DQE・散乱グリッドの物理模擬）
- 検出器背後からの後方散乱（終端型の近似として許容。上記1に明記）
- EGS5相互検証（**ユーザー判断により受入条件に含めない**。文献値・解析解で判定し、
  EGS5照合は必要になった時点で `vive-crosscheck` の別作業として実施する）
- 分散低減（next-event estimation / forced detection）

## Phase 1a: 2.5D heightfieldプリミティブ（幾何の単独ゲート）

Codexレビュー指摘（採用）により、当初1本だったPhase 1を1a/1bに分割する。
**heightfieldは最も輸送中核に近い変更なのに単独の検証ゲートがなかった**——
分割しないと、Phase 1の失敗時に「heightfield輸送の誤り」「2.5D近似の限界」
「逆問題・正規化の誤り」を切り分けられない。

厚さマップを検出器面に垂直押し出しした形状を、解析的サーフェストラッキングの思想を
保ったまま実装する（ray交差が「列ごとの1D問題」に帰着する）。検証は幾何と物理のみ:
解析交差、`material_at`、隣接セル境界、斜入射、既存 box/cylinder/sphere の非退行、
Beer-Lambert。**補正アルゴリズムはこのPhaseでは一切扱わない。**

## Phase 1b: クローズドループfeasibility実証（このプロジェクトの決定実験）

**シミュレーション閉世界で自己一貫性を検証する。** 実測画像は使わない
（画素値↔線量の較正・検出器応答・焦点外放射という別問題を混ぜないため）。

1. 既知の3Dシーン（胸部相当の多材料ファントム）でグリッドなし観測像を生成
2. **観測像だけを入力**として、厚さマップを逆算（Beer-Lambert逆問題。実効μの決め方が論点）
3. 厚さマップを押し出した2.5Dモデルを構築（Phase 1aの成果物を使う）
4. MCで散乱像を推定し減算
5. **真の一次線像（手順1でPhase 0のタリーが弁別集計済み）との誤差マップ**を評価
6. 反復（散乱混入による厚さ過小評価の補償）

手順1で正解が既知の状態でアルゴリズム全体を採点できる。これがこのプロジェクトで
最も情報量の多い実験。

**評価はSPR別に層別化して報告する**——SPRが大きい部位ほど推定誤差が画像に直結するため、
全体平均だけの報告は誤解を招く。

### 停止条件

誤差が事前登録した基準を満たさない場合、**基準を測定に合わせて動かさない**。
不合格として記録し、原因（厚さ逆算の誤差／2.5D近似の限界／統計不足）を切り分けてから
次の設計判断をする。

## Phase 2: 精度向上（Phase 1bの結果を見てから内容を確定する）

候補（Phase 1bの誤差の内訳によって優先順位が変わる）:
- 反復回数の最適化、厚さ逆算の実効μ決定法の改善
- 二材料分解（軟部/骨/肺のセグメンテーション→材料割当）
- 散乱像の粗ビン解像度と平滑化の最適化（粗ビンのRを含む、Phase 0の判断5の積み残し）
- 分散低減（next-event estimation）による計算時間短縮
- グリッド効果模擬（一次線透過率・散乱線除去率）
- 検出器応答（吸収効率・DQE）、検出器背後の後方散乱の影響評価

**Phase 1bの結果を見る前にPhase 2の内容を確定しない。**

## Phase 3: 出口の選択（技術判断ではなく戦略判断）

- 実測画像への適用（画素値↔線量の較正、検出器応答、ヒール効果の扱いが必要）
- MC教師データ→DL化（散乱像とノイズ除去を同時に学習。リアルタイム化の唯一の現実的経路）
- 学会報告（2026-11-14/15 九州放射線医療技術学術大会。**差別化点を明確にする必要あり**
  ——近傍先行研究として Radiol Phys Technol 2024 のWEPL+DL散乱補正が存在する）

## 量子ノイズの扱い（全Phaseを貫く方針）

**MCでノイズの実現値を計算して差し引くことは原理的に不可能**（独立な実現値の減算は
分散を加算しノイズを√2倍にする）。MCの役割は「ノイズの設計図の供給」に限定する:
(1) ピクセル毎の量子ノイズ予測（**実光子数へスケールした検出scoreのモーメント**であって、
MC統計誤差Rではない。上記Phase 0判断7の訂正を参照）、(2) デノイザ学習用の
クリーン/ノイジーペア生成、(3) CNR改善を「散乱補正の寄与」と「デノイズの寄与」に
分離した誠実な評価。

## 全Phaseに共通する変更禁止範囲

- `chatcarlo/physics.py`・`chatcarlo/materials.py`・`chatcarlo/spectrum.py` の
  物理モデル・断面積データ（EGS5相互検証済み。本プロジェクトは物理を変更しない）
- `chatcarlo/data/` 配下のデータファイル（NIST XAAMDI / ICRP74）
- `chatcarlo/tally.py` の既存推定器の**数式**（`_batch_variance`・`standard_error`・
  `relative_error`）——共通ヘルパーへの括り出しは可だが、
  **推定式そのものと既存の呼び出し結果は変えない**（ビット一致を維持する）
- `docs/egs5_crosscheck/` 配下の既存結果
- 既存テストの期待値（新機能のために既存の合格基準を緩めない）

## 書かなかったこと（プロジェクト全体としてのスコープ外）

- CBCT・トモシンセシスへの拡張（本プロジェクトは2次元単一投影に限定）
- 実機との較正・臨床評価（Phase 3で改めて判断する）
- リアルタイム処理（MC直接では不可能。DL化の路線でのみ検討）
- 散乱グリッドの物理的な格子構造そのもののモデリング（グリッド効果は
  一次線透過率・散乱線除去率という集約パラメータで模擬する）
- 電子輸送（カーマ近似のまま。診断エネルギーでは妥当）
- 厚みのある検出器物体としてのモデル化（Phase 0判断1で終端型平面を採用したため。
  検出器応答が必要になったらPhase 2で重み関数として導入する）

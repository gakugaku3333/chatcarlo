## 目的

親計画の G2 の合格条件は 2 つ。
- `transport.py` の飛跡長タリーと、ボクセルごとに統計的に一致すること。
- 2026-10-07 の EGS5 60 keV の組を GPU で再実行し、同じ判定基準で比べること（既存の 42 合格・1 不合格・4 統計不足と、Rayleigh の警告はそのまま引き継いで報告する）。

この計画が答える問い: **G1 の核（CPU の双子と CUDA）に、本番と同じ定義のカーマ・H*(10) の飛跡長タリーを足したとき、本番と同じ値（統計の範囲で）を返すか。また、60 keV の EGS5 比較を GPU で同じ判定にかけるとどうなるか。**

## 0. 前提事実（検証済み、2026-10-22 に実行）

**F7 既存コードとの契約**
- 本番の格子のタリー: `tally.py` の `VoxelGrid` と `accumulate_track_length_multi`（464・483 行）。
  - 線分とボクセルの重なりの長さを厳密に求める（3D DDA）。カーマと H*(10) は 1 回の走査を共有する。
  - 不確かさはバッチ統計（バッチ＝`batch_size` 履歴。`kerma_sum2`・`h10_sum2`・`n_batches_hit`）。
- 係数の補間（CLAUDE.md のデータの来歴の表）:
  - μen/ρ は `materials.mu_en_rho`。NIST XAAMDI の同梱表を、log-log の **PCHIP** で補間する（`_muen_interpolator`、348 行。`scipy.interpolate.PchipInterpolator`）。
  - h*(10)/Φ は `dose_coefficients.h_star_10_per_fluence`。ICRP 74 の表を **log-log 線形**で補間し、10〜10000 keV の外は端の値に固定する。
- **細かい格子への焼き込みでは足りない**（実測。1〜150 keV の対数一様の 20 万点で、焼き込んだ格子の対数線形補間と本番の関数を比べた）:

| 格子の点数 | 水の μen 最大相対差 | 鉛の μen 最大相対差 | h*(10) 最大相対差 |
|---|---|---|---|
| 1,024 | 2.6e-5 | 5.6e-1 | 3.1e-3 |
| 4,096 | 1.6e-6 | 3.9e-1 | 1.2e-3 |
| 16,384 | 1.0e-7 | 6.1e-1 | 4.1e-4 |

  鉛は吸収端で、h*(10) は 10 keV の端の固定と表の折れ目で、格子を細かくしても差が残る。
  → **GPU には本番と同じ形を渡す**。μen は PCHIP の区間の境と 3 次の係数を、h*(10) は ICRP の表そのものを渡す。
- 60 keV の EGS5 再検証（`docs/egs5_crosscheck/revalidation_2026_10_07/`）は、**格子のタリーではない**。
  - `run_chatcarlo.py` が、`transport_photons` の飛跡記録（`TrajectoryRecorder`）から、**47 個の大きさのそろわない箱**（中心軸の PDD 15 個、表層と深さ 9〜10 cm の側方 16 個ずつ）との重なりを厳密に求める。
  - 箱ごとに `長さ × E × μen(水)` を足す。数えるのは水の線分だけ。
  - 不確かさは**履歴ごと**（各履歴の寄与の和と 2 乗和、M = 履歴数）。
  - 本計算の条件（事前登録）:
    - PDD/OCR: 5×10⁶ 履歴（seed 1、batch 10⁵）
    - BSF の薄層: 5×10⁵（seed 1）
    - BSF のファントム: 5×10⁵（seed 2）
  - 線源は parallel 10×10 cm で、z=−1e-4 から +z 向き。60 keV 単色。蛍光あり。`bbox_margin_cm=0.01`。
  - EGS5 の値は `comparison.csv`・`comparison.json` にある（今回は EGS5 を走らせ直さない）。
- G1 の核（`chatcarlo/gpu/g1_history.h`）: 1 履歴の中で、線分（x→x+d·ds、エネルギー e、材料 m）を順に作る。今はタリーを持たず、`g1_add_record` が材料ごとの吸収と検出器の画像だけを足す。
  - `engine.gpu_engine_compatible` は `dose_grid` を拒む（11 行）。
- G4 の Colab の経路（承認・照合・受領票）は検出器の画像だけを扱う。格子は扱わない。

## 1. 決めること（骨子のレビューで確かめたい点）

| # | 決めること | 推奨 | 理由 |
|---|---|---|---|
| E1 | タリーの形 | **格子を本体の機能、箱を検証専用にする**（Codex の代替案を採用）。(a) 一様な格子（本番の `--dose-grid` と同じ。カーマと H*(10)）、(b) 60 keV の 47 箱（水の線分だけ・カーマだけ。検証のランナーからだけ使い、一般の任意箱の API にはしない）。**共有するのは係数の評価とモーメントの更新だけで、走査は目的別に 2 つ書く** | (a) は親計画の合格条件、(b) は 60 keV の組を同じ定義で再実行するのに要る。1 つの採点関数に縛るより、走査を分けたほうが明瞭（格子に統一する案は、ROI の対応表が要り、セルの 2 乗和を後から足すと元の SEM を再現できない。ホストで採点する案は飛跡の回収が要る） |
| E2 | 採点の場所 | **装置の上で、線分ができるたびに足す**（アトミック加算）。線分をホストに送ってから足す方式は採らない | 線分の記録は 10⁶ 履歴で数百 MB になり、転送が律速する |
| E3 | 不確かさ | (a) 格子は本番と同じ**バッチ統計**（バッチごとの和をホストに返し、ホストで本番と同じ式 ΣS_b²/n_b（`tally.py` 96 行）と寄与バッチ数を足す）。(b) 箱は 60 keV と同じ**履歴ごとの統計**（履歴の中で箱ごとの寄与を局所に貯め、履歴の終わりに和と 2 乗和を足す。箱は最大 64 個） | どちらも、比べる相手の定義に合わせる |
| E4 | 係数の補間 | μen は PCHIP の区間の境と係数を、`PchipInterpolator` の `x`・`c` から**スクリプトで**焼き込み、装置で同じ 3 次式を評価する。h*(10) は ICRP の表と端の固定を写す。どちらも手で打たない | 0 節の実測。データの来歴の規則 |
| E5 | 段の分け方 | **G2a**: 核のタリーと Python の API（`run_transport(engine='gpu', dose_grid=True)` と、60 keV 用の専用ランナー）、関門 0〜3 まで。**G2b**: CLI と Colab の承認の層に格子を通す（受領票・照合・.npz の保存）。G2b は G2a の合格後に別の詳細計画で決める | 承認の層まで入れると計画が 25 KB を超える見込み。G2a の結果で G2b の形が変わりうる |

**格子の契約**: GPU の格子の原点・形・大きさは、本番と同じ `geometry.tally_bbox_min/max` と `VoxelGrid.from_bbox(..., resolution)` で決め、ホストから渡す。`run_transport` の GPU 分岐（`transport.py` 502 行）は今 `grid_resolution_cm` を渡していないので、渡す変更だけを対象範囲に入れる。

## 2. 事前登録する判定（G2a）

**G2a の完了**は、関門 0〜2 の合格と、関門 3 で全 47 箱と BSF を旧基準で分類・報告できたこと。**関門 3 の各箱の物理比較の合否は、完了の条件にしない**（親計画も 42・1・4 の再現を求めていない）。

- **関門 0a（関数単位）**: C++ の「線分と箱の重なり」が、Python の `_segment_box_overlap_cm`（60 keV の監査済みの関数）と、ランダムな線分 10⁶ 本で相対 1e-12 以内（または絶対 1e-12 cm 以内）。C++ の μen と h*(10) の評価が、本番の関数と相対 1e-12 以内（1〜150 keV の 20 万点と、表の格子点・吸収端の両側）。
- **関門 0b（格子への分配、決定論的）**: 同じ固定の線分と重み（エネルギー・材料）を、C++ の格子タリーと `tally.accumulate_track_length_multi` に与え、ボクセルごとに相対 1e-12 以内（ゼロはゼロ）。線分には、軸に平行・負の向き・面や辺や頂点を通るもの・格子の外から入るもの・長さ 0・検出器で打ち切られたもの、を含める。スカラーの参照として `tally_njit.py` も使える。
- **関門 0c（モーメントと統計）**: 手計算できる人工の履歴とバッチ（同じ箱への複数の線分、寄与 0 の履歴、端数の最後のバッチ、バッチ 1 個、不確かさ無効）から、和 T、2 乗和 Q、SEM、R、寄与バッチ数を独立に作り直し、格子（バッチ統計）と箱（履歴ごとの統計。2 乗するのは履歴ごとの寄与の和）の実装と一致させる。
- **関門 1（CPU の双子 対 `transport.py`）**: 下の 2 シーンを、本番（NumPy）と CPU の双子で**独立に**回し（線源の配列も別。共有すると両者の推定に共分散が入るため）、ボクセルごとのカーマと H*(10) を比べる。z = (双子 − 本番) / √(SEM_双子² + SEM_本番²)。
  - シーン（2 cm 格子、4×10⁶ 履歴、バッチ 2×10⁵ で 20 バッチ）:
    - S1 `examples/water_phantom_pdd_ocr.yaml`（60 keV 単色、parallel、水）
    - S2 `docs/validation/gpu/g2/scene_lead_slab.yaml`（80 kV、ろ過 2.5 mmAl、rect 20×20 cm・SID 100 cm、水 30×30×20 cm と骨 4 cm 角、その下に鉛 0.5 mm 40×40 cm、背景は空気）
  - 本番の参照は**計画の段階で作って固定した**（2026-10-22、`data/gpu_g2/ref_water.npz`（seed 2201）と `ref_lead.npz`（seed 2202）。CLI の `run ... -n 4e6 --batch-size 200000 --dose-grid --resolution 2`。sha256 は aa17a90a…0abe と 10ea4b89…40d8。コミットしない）。走らせ直さない。
  - 双子の種: S1 は seed 2211、S2 は seed 2212（`source_seed` は G1 の既定の導出）。
  - 判定対象: 両者とも R≤0.10 かつ寄与バッチ≥25% のボクセル（量ごと）。参照で数えた対象の数: S1 はカーマ 148,180（水 2,250）・H*(10) 152,937、S2 はカーマ 83,453（水 2,466、骨 12、鉛の層を含むボクセル 1,440）・H*(10) 95,673。
  - 判定（量ごと、シーンごと。すべて満たして合格）:
    1. 外れ: max |z| ≤ t.isf(0.005/N, 19)（N は判定対象の数。全体の誤り率 1% のボンフェローニ。各 SEM が 20 バッチからなるので自由度 19 の t で保守的にとる。N=8.3 万で 8.18、15.3 万で 8.52）。大きな誤り（取り違え・桁違い）を拾う。
    2. 広がり: |z|>3 の割合 ≤ 1.0%（正規なら 0.27%、t19 なら 0.74%）。
    3. 偏り: 領域ごとの合計（S1: 水・空気。S2: 水・骨・鉛の層・空気。領域はボクセル中心の材料、鉛の層は z が [−0.05, 0] と重なるボクセル）の差の z が |z|≤3。合計の SEM は、各バッチの領域の和から求める（ボクセル間の共分散を保つ）。全格子の合計も同じ方法で |z|≤3。細かい系統の差は、ボクセルごとより、この合計で検出する。
    4. 採点漏れ: (i) 判定対象が 0 個なら「統計不足」で合格にしない。(ii) 参照で判定対象のボクセルが、双子で 0・非有限・寄与バッチ 0 になった数が 0。(iii) 判定対象の最低数: 水 1,000、空気 1,000、骨 8、鉛の層 500（参照の数の約 2/3 以下に置いた）。下回れば「統計不足」で止まって報告する。
  - 読み方: 「この標本の精度で不一致を検出しなかった」ことを示す。数 % 以内の一致の保証ではない。報告には対象数、相対差の分布（中央値と 95% 範囲）、z² の平均を添える。
- **関門 2（GPU 対 CPU の双子、Colab T4）**: S2 と 60 keV の PDD の幾何で、それぞれ 10 バッチ × 10⁵ 履歴を、**同じ線源の配列と同じ種**で CPU の双子と GPU に回す。**G1 の `validation.paired_judge` を引き継ぐ**（丸めの上限の内側、または対応するバッチの差が 3 SEM の内側）。対象は格子の 2 量、箱の和と 2 乗和、寄与バッチ数、履歴数。飛跡長のタリーは 1 履歴が同じボクセルに何度も足すので、丸めの上限に使う加算の回数は、光子数ではなく実際の寄与の加算回数を数えて使う。`image_regression`（G4 の画像用）は使わない。丸めの上限は、量ごとに |Δ| ≤ (k_cpu + k_gpu + 2B + C)·2⁻⁵²·S。k は実際の加算回数（格子に数えの配列を足して両方で数える）、S は寄与の絶対値の和、B=10（G1 と同じ）、C=16（`log`・`exp` などの数学関数の CPU と GPU の差の余裕。1 つの寄与あたり）。
- **関門 3（60 keV の EGS5 比較を GPU で）**: 0 節と同じ 3 本（PDD/OCR、BSF の薄層、BSF のファントム）を、同じ履歴数・バッチで、GPU の核と箱のタリーで回す。
  - 判定は 2026-10-07 の事前登録と**同じ**（従来の 2σ・2% と、統計不足の扱い、補助の Bonferroni 判定）。EGS5 側は保存済みの値を使う。
  - 種は GPU 用に新しく決め、本計算の前にこの計画に書く。**結果を見て種や履歴数を選び直さない。**
  - 報告では、2026-10-07 の NumPy の結果（42・1・4）と GPU の結果を並べる。食い違いがあっても、どちらかを正とはしない（新しい標本なので、統計で変わりうる）。
  - EGS5 の Rayleigh の警告は、そのまま引き継いで書く。
  - BSF の分子（ファントム）と分母（薄層）は、独立な輸送の乱数列（別の種）を使う。BSF の合成相対 SEM の条件（<1%）も旧事前登録から引き継ぐ。

## 5. 実装の形（詳細）

**C++（`chatcarlo/gpu/`）**
- 新しいヘッダー `g2_tally.h`:
  - `g2_muen(material, e)`: PCHIP の区間を二分探索し、`c[0..3]` の 3 次式を log E で評価して exp を返す。
  - `g2_h10(e)`: ICRP の表の log-log 線形補間。表の端で固定する。
  - `g2_grid_segment(...)`: 本番の `_segment_grid_traversal_accumulate` と同じ規則の 3D DDA。格子の外はクリップし、境界の上の点は本番と同じ側のボクセルに入れる（規則は実装の前に本番のコードを読んで、テストに書く）。カーマ（E·μen·ρ·長さ）、H*(10)（h·長さ）、加算回数の 3 つの配列に足す。
  - `g2_box_segment(...)`: 47 箱の検証専用。水の線分だけ、箱ごとの重なり（`_segment_box_overlap_cm` と同じ式）× E × μen(水)·ρ を、履歴の局所の配列（最大 64）に足す。
- `g1_history` に、省略できるタリーのポインタを足す（既定は null で、今の動きと 1 ビットも変えない）。線分ができる位置（`ds` が決まり、検出器で打ち切られた後、位置を進める前）で採点する。本番の `transport.py` 162 行と同じ位置。
- **G1・G4 の関数の引数の並び（ABI）は変えない**。G4 の照合（`core.CPU_INPUTS`・`CUDA_INPUTS`）が位置で引数を観測しているため。タリーつきは新しい入口 `g2_histories`（CPU）と `g2_histories_kernel`（CUDA）にする。
- 箱の履歴ごとの統計: 履歴の終わりに、局所の配列の各箱について和と 2 乗和を足す（GPU はアトミック加算）。

**係数の表（Python、`chatcarlo/gpu/g2_tables.py`）**
- `materials._muen_interpolator(key)` の `x`・`c` と、`dose_coefficients._table()` を読み、材料の順番は G1 の束と同じにして、固定長の配列に詰める。束（`bundle.py`）に足して、目録にハッシュを書く。値は手で打たない。

**Python の API**
- `run_transport(engine='gpu', dose_grid=True, grid_resolution_cm=r)` で、本番と同じ `VoxelGrid.from_bbox` の格子を作り、GPU の結果を本番と同じ `VoxelGrid`（カーマ、H*(10)、`kerma_sum2`、`h10_sum2`、`n_batches_hit`、`n_batches`、`n_histories`）に入れて返す。バッチごとの和を受け取り、`end_batch` と同じ式で統計を足す。
- `engine.gpu_engine_compatible` は `dose_grid` を受け付ける。`transport.py` の GPU 分岐で `grid_resolution_cm` を渡す。
- 箱は API にしない。`docs/validation/gpu/g2/run_egs5_60kev.py` だけが使う。

**検証のファイル（`docs/validation/gpu/g2/`）**
- `run_gates.py`: 関門 0〜2（G1 の `run_gates.py` と同じ形。Colab は G1 と同じ Colab CLI の手順）。
- `run_egs5_60kev.py`: 関門 3。旧 `run_chatcarlo.py` の箱の定義・線源（`_sample_parallel_beam`）・ビンを読み込み、GPU の核で採点し、旧と同じ形の JSON を書く。

## 背景: 特定済みの不一致（1件目・終点側）

不一致は浮動小数点の加算順ではなく、**境界面の扱いに関するセマンティクス差**である
（レビューで区間単位まで切り分け済み）。

問題の区間（water60_free、`batch_size=60_000` の batch1、segment index 212898）:

```python
origin    = [-3.037619819265908, 0.0, 0.0]
direction = [0.018394208153120428, 0.6110258451767133, -0.7913969103000736]  # 単位長
length_cm = 1.5015538205527557
w_kerma   = 1.9965502538144548
w_h10     = 0.5335686225843084
# grid = VoxelGrid(np.array([-5.01, -50.01, -50.01]), (6, 51, 51), 2.0)
```

この区間の**終点はx方向のボクセル境界面から 3.811e-08（面インデックス単位）**に着地する。

| 実装 | 配分先 | 挙動 |
| --- | --- | --- |
| numpy（参照） | 2ボクセル `(0,25,24)` `(0,25,25)` | 終点近傍の面を交差面として**列挙しない** |
| njit（試作） | 3ボクセル（+`(1,25,24)`） | 面を通過とみなし 4.14e-06 cm の薄片を追加 |

合計長は**厳密に一致**（差 0.000000e+00）。総量は保存され、**境界での配分先だけが異なる**。

参照実装の該当ロジックは `chatcarlo/tally.py:376-377`:

```python
m_lo_k = np.ceil(p_small + _EPS_PLANE).astype(np.int64)
m_hi_k = np.floor(p_big  - _EPS_PLANE).astype(np.int64)
```

`_EPS_PLANE = 1e-7`（`tally.py:254`、単位は面間隔）。

**用語の訂正**: これは座標を面へ「スナップ」する処理ではない。参照実装は
**区間自身の始点・終点から `_EPS_PLANE` 以内にある面を交差点リストから除外し、
残った部分区間を中点で再分類する**（`tally.py:437-448`）。この違いが下記の2件目・3件目の原因になる。

## 修正しきれない残差（Codexレビューで判明した追加の不一致源）

境界面の列挙だけを直しても参照とは一致しない。以下の3つも同時に揃える必要がある。

### 2件目（始点側）: probe方式では中点分類と一致しない

試作は入口直後の微小 probe 点で初期ボクセルを決める（`dda_njit_prototype_benchmark.py:62-66`）。
参照は面を除外したあと、結合された部分区間の**中点**で分類する（`tally.py:444-448`）。

正方向の区間が境界のごく手前（`_EPS_PLANE` 以内）から始まる場合、
- 参照: その面を消し、次の面までを1区間として、中点が属する**境界後**のセルへ全長を配分
- 試作: probe が**境界前**のセルに入り、そこへ配分

となり得る。**「probe方式のままでよい」という前版の記述は撤回する。**

### 3件目: `tol = 2e-12` の同着判定は独立したセマンティクス差

試作は複数軸の境界到達時刻が `2e-12 * max(1, |t|)` 以内なら同時に更新する
（`dda_njit_prototype_benchmark.py:110-116`）。参照は各軸の面を個別に列挙し、
**厳密に同じ t** ならゼロ長区間として落とすが（`tally.py:439`）、
**近いだけ**なら正の薄片を残す（`tally.py:427`）。

したがって2〜3面への到達時刻が非常に近い（ただし不一致な）ケースで、
参照は薄いedge/cornerボクセル区間を残し、試作はそれを飛ばす。

### 4件目: clamp は「捨てる」意味論ではない

試作は初期セル添字をグリッド範囲へ clamp する（`dda_njit_prototype_benchmark.py:67-78`）。
参照の `voxel_index` は clamp せず、範囲外として**破棄**する（`tally.py:108`）。
通常はAABBクリップで同じ結果になるが、境界丸めやprobeの丸めが絡む場合は一致しない。

## なぜ前計画の検証で捕まらなかったか（テスト設計の教訓）

前計画の正しさ検証は最大誤差0で全PASSだったが、
- 境界ケースは手で座標を構成したもので、この配置（**長い走査の末に終点が面の1e-7以内へ着地**）を含まない
- 6000本のランダムfuzzは、端点が面の1e-7以内に落ちる確率が実質ゼロ

という盲点があった。加えて、**多数の区間を一括集約して比較すると、同一ボクセルへの誤配分が
加算で相殺・隠蔽され得る**。本計画では境界fuzzを**区間単位（または小グループ単位）で比較**する。

## 受入条件（検証可能な形で列挙）

### 1. 参照セマンティクスへの一致（4点すべて）

**推奨する実装方針**: 参照実装の手順をそのままスカラーへ移植し、構造的に等価にする。すなわち
①AABBクリップで `t_enter`/`t_exit` を求める → ②各軸で
`ceil(p_small + _EPS_PLANE)` 〜 `floor(p_big - _EPS_PLANE)` の面インデックスを列挙 →
③全交点＋両端点を区間内でソート → ④隣接ペアのうち**正の長さ**を持つものだけを採用し、
**中点**でボクセルを決め、範囲外は**破棄**する。
1区間あたりの交点数は高々数十のため、区間内ソートは小配列の挿入ソート等で十分速い。

Amanatides-Woo型のstepping方式を維持してもよいが、その場合は下記4点すべてを参照と一致させ、
受入条件2のfuzzで一致を証明すること。

- [ ] **面の列挙**: 区間自身の端点から `_EPS_PLANE` 以内の面を交差面として扱わない。
      定数は `chatcarlo.tally._EPS_PLANE` を **import して使う**（値を複製しない）。
- [ ] **初期セル/分類**: 各部分区間を**中点**で分類する（probe方式のままにしない）。
- [ ] **同着判定**: 到達時刻が**厳密に等しい**場合のみゼロ長として落とす。
      近いだけの場合は正の薄片を残す（`tol = 2e-12` による同時更新を廃止するか、
      廃止しない場合は受入条件2の近接同着fuzzで参照と一致することを示す）。
- [ ] **範囲外の扱い**: 添字を clamp せず、範囲外の部分区間は**破棄**する。

### 2. 回帰ケースと境界近傍fuzz

- [ ] **回帰ケース**: 上記「背景」の完全精度リテラルをそのまま埋め込んだ名前付きケースを追加する。
      参照とボクセル単位で一致すること、かつ **`voxel(1,25,24)` がゼロであること**を個別にassertする
      （非ゼロボクセル集合の一致だけに頼らない）。
- [ ] **境界近傍fuzz**: 以下をすべて満たすよう生成する。総本数は
      「3軸 × {始点, 終点} × {正方向, 負方向} × オフセット水準」で構成し、
      **各組み合わせにつき50本以上**とする（前版の「300本ずつ」は本数の解釈が曖昧だったため差し替え）。
  - オフセット水準は乱数範囲だけでなく、**決定的な値 `0`, `0.5*EPS`, `0.99*EPS`, `1.01*EPS`, `2*EPS`**
    を必ず含める（`_EPS_PLANE` の両側をまたぐこと）
  - 境界の**両側**（手前・奥）と、方向の**正負**を含める
  - 区間自身の端点だけでなく、**AABBクリップによって生じた `t_enter`/`t_exit`** が
    面の近傍に来るケースも含める
  - 2軸・3軸の境界到達時刻が**厳密に同着**するケースと、**`2e-12` の内外**に入るケースを含める
  - 斜め方向（3軸とも非ゼロ）を含める
  - 最初の境界までが**短い**ケースも含める（長い走査だけにしない）
  - 生成後、実際に再計算した面インデックス距離が**狙った範囲にあることをassert**する
  - **区間単位（または互いに異なるセルへ配置した小グループ単位）で比較する**
    （一括集約すると誤配分が加算で隠れるため）
- [ ] 既存の境界ケース・6000本fuzz・chest_room由来区間の検証は**すべて残し**、
      修正後も引き続きPASSすること（回帰させない）。

### 3. 正しさの再確認（速度測定より先に完了させる）

- [ ] `dda_njit_prototype_benchmark.py --mode correctness` が全PASS。
- [ ] `dda_njit_e2e_benchmark.py --mode correctness` が
      **1バッチ条件・複数バッチ条件（60k×3+20k）ともPASS**。
      許容は `atol=2e-10, rtol=2e-12` を**維持する**（緩めない）。
      ただし**許容値だけを検出装置とみなさない** — 薄片の重み付き寄与が `atol` 未満だと
      値比較を通過し得るため、**非ゼロボクセル集合の一致**を必ず併用する（既存どおり）。
- [ ] 万一まだ不一致が残る場合は、**許容を緩めず**、前回と同じ手順
      （バッチ単位 → 二分探索で区間単位まで特定）で原因区間を突き止め、
      その origin / direction / length_cm と**両実装のボクセル別配分**を報告して停止する。

## 実装方針

- `_EPS_PLANE` は `chatcarlo.tally` から import する。値をハードコードで複製しない
  （本番側が変わったときに黙って乖離するのを防ぐ）。
- 参照手順の移植（推奨方針）を採る場合も、前計画で確認済みの既存ケース・fuzz・chest_room由来区間が
  引き続きPASSすることを回帰の担保とする。
- 修正後に速度が落ちる可能性がある（境界判定・区間内ソートの追加分）。それ自体は許容し、
  end-to-end の実測で最終的な採否を判断する。

## 書かなかったこと（スコープ外を明示）

- `chatcarlo/kernel.py` への恒久的な組み込み・切り替えスイッチの追加は行わない
  （高速化が確認され、ユーザーが採用を決めた後の、次の計画で扱う）。
- DDAをprange領域の内側へ移す設計・データ競合の回避策は一切扱わない。
- 参照実装（`chatcarlo/tally.py`）側の `_EPS_PLANE` や中点分類の妥当性そのものは検討しない。
  今回は**参照に合わせる**のが目的であり、参照の是非は別問題。
- chest_room等、box以外の形状でのend-to-end測定は行わない（kernel未対応のため不可能）。

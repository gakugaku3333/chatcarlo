## 背景

[docs/plan_chatcarlo_speedup_post_egs5.md](../../plan_chatcarlo_speedup_post_egs5.md) B-2で、輸送カーネル(njit prange並列)を高速化した結果、
既存の監査済みDDA(`tally.accumulate_track_length_multi`、ベクトル化numpy、参照実装と完全共有・無変更)が
新たなボトルネックとして支配的になった(water60_free・N=2e5・resolution=2cm・8スレッド条件で全体0.538秒中0.402秒=75%、
cProfileで74〜76%再現の実績あり — この内訳自体は信頼できる)。
3倍を狙う唯一の経路はDDA自体をカーネル内にnjitスカラーで再実装することだが、同計画は**このスコープでは着手せず**
「将来の別計画として切り出す」と明記している。本計画がその切り出し。

## 目的（1〜3行）

「njitスカラーDDAを実装すれば現行のベクトル化numpy DDAより速くなり、かつ3倍化に届く余地がある」という
**未検証の前提**を、本実装に着手する前にプロトタイプで反証可能な形で検証する。この前提が崩れれば、3倍化プロジェクト自体を始めない。

## 受入条件（検証可能な形で列挙）

### 1. 実装

- [ ] `_segment_grid_traversal_accumulate`(`chatcarlo/tally.py:302`)と機能的に等価な処理(区間→ボクセル交差分解→kerma/H\*(10)積算)を行う、njitスカラー版DDAプロトタイプ関数を実装する。並列化はしない(prangeなし、既存の`accumulate_track_length_multi`もシングルスレッドのため、フェアな比較条件を保つ)。
- [ ] 入力契約を明記する: **方向ベクトルは単位長であること**(現行関数は`length_cm`を幾何学的長さの上限として使うため、非正規化方向では意味が変わる)。

### 2. 正しさ(ボクセル単位。速度比較より必ず先に完了させる)

グリッド合計の一致だけでは、角・辺通過時の「誤った軸だけを進めて総量は保存したまま隣のボクセルへ誤配分する」バグを見逃す
(このリポジトリのDDAは過去に決定的中点法の系統的過小スコア・境界位相アーチファクト等、複数回この種のバグを踏んでいる)。
以下をすべて確認する:

- [ ] kerma配列・H\*(10)配列のボクセル単位比較(グリッド合計一致は補助的な保存則チェックとしてのみ残す)
- [ ] 非ゼロボクセル集合の一致
- [ ] 最大絶対誤差・最大相対誤差の両方を報告する(単一レイの交差長そのものには厳しい絶対誤差、複数レイの集積グリッドには`rtol`/`atol`を明示 — スカラー加算と`np.add.at`は加算順が異なり得るため、集積後の絶対誤差1e-9は過剰に厳しい可能性がある)
- [ ] 以下の境界ケースを単一レイで個別に検証する(現行実装の数値規約: `abs(direction) < 1e-12`を平行扱い[tally.py:338]、境界面判定`_EPS_PLANE = 1e-7`[tally.py:254]、`t_exit > t_enter`のみ有効区間[tally.py:350]に基づく):
  - x/y/z各軸の正方向・負方向
  - 格子外→格子内→格子外、完全に格子外、完全に格子内
  - 始点/終点が外周面・内部面ちょうど、面上を平行に進むレイ、上端`hi`面上を進むレイ
  - 2軸同時境界通過(辺)・3軸同時境界通過(頂点) — 該当する全軸を同時に進めることを確認
  - 方向成分が0、`1e-12`の直下・直上
  - ゼロ長・極短区間、1ボクセルだけを横切る区間、数百〜数千ボクセルを横切る長区間
  - 非立方体グリッド
  - 複数レイが同一ボクセルへ加算される場合、kerma/H\*(10)で大きく異なる重み、ゼロ重み
- [ ] ランダムfuzzによるボクセル単位比較(境界ケース列挙の漏れを補完)
- [ ] 上記とは別に、chest_room由来の散乱方向を含む区間集合(複数方向・複数材料)でも一致を確認する(一般化確認 — water60_freeは鉛筆ビームで軸方向成分が支配的なため、それだけでは一般3D DDAの正しさを代表しない)

### 3. 速度比較(正しさが全て確認できてから)

0.402秒は統合実行のcProfile累積値であり、JIT初回コンパイル・配列変換・Python呼び出しオーバーヘッド等を含む。
プロトタイプは同じ土俵で測る必要があるため、以下の2段階で切り分ける:

- [ ] **入力生成の固定**: 固定seedでkernel由来の区間配列(o, d, ds, e, mat)を一度だけ生成し、同一の配列・グリッド・重みを両実装(既存の`accumulate_track_length_multi`とプロトタイプ)にそのまま渡す。入力生成・JITウォームアップは計測対象から除外する。
- [ ] **主要速度ゲート(water60_free)**: 元の0.402秒と同一条件(water60_free・N=2e5・resolution=2cm)の区間集合で、同一プロセス内で両targetを毎回ゼロクリアしながらAB/BAを交互に自動実行し(手動での別プロセス実行ではなく、環境差・JIT差を減らす)、`perf_counter`で直接比較する。**この直接A/B結果**(0.402秒の再現値そのものではない)を反証条件の基準とする。参考として、統合実行での0.402秒の再現値も別途1回報告する(健全性確認用、合否判定には使わない)。
- [ ] **反証条件は二段階ゲートとする**:
  - ゲートA(単純な速度比較): プロトタイプのDDA単体時間が既存実装のDDA単体時間を下回るか
  - ゲートB(3倍化に値するか): ゲートAの結果と、実測されたDDA以外の残余時間(全体0.538秒からDDA分0.402秒を除いた0.136秒相当)から、Amdahl則によるend-to-end予測改善率を算出する。予測改善率が3倍に届く見込みがなければ、ゲートAを通過していても3倍化プロジェクトには**進まない**(「単に速い」と「3倍化に十分」を混同しない)。
  - ゲートA・Bの計算式と閾値は実行前に`docs/plan_dda_njit_premise_check.md`に事前登録し、結果に合わせて後から変更しない([[feedback-critical-code-review]]の「基準を測定に合わせて動かさない」規律と同種)。
- [ ] 一般化確認として、chest_room由来の区間集合でも速度比を参考値として報告する(主要判定はwater60_freeのみで行う)。

### 4. 将来のカーネル統合に向けた既知の制約(今回は検討のみ、実装しない)

- [ ] 現在のkernelはprangeチャンクごとに専用の区間バッファへ書き、その後シリアルにDDAを実行する設計(`kernel.py:1043`, `kernel.py:1096`)。将来DDAを輸送カーネル内(prange並列部)へ統合すると、複数スレッドが同じkerma/H\*(10)グリッドを更新しデータ競合する。主な選択肢(チャンク/スレッドごとの専用グリッド+reduce、atomic加算、区間バッファを残しDDAのみ後段実行)を短く記録する。
- [ ] **今回のシングルスレッド採択結果だけで「カーネル内統合可能」と判断しない**ことを明記する。次段階(統合実装)の成立条件として、競合回避方式の選定とメモリ見積もりが別途必要であると`docs/plan_dda_njit_premise_check.md`に残す。

### 5. 記録

- [ ] 結果(ボクセル単位の正しさ一致・ゲートA/Bの判定・棄却/採択)を`docs/plan_dda_njit_premise_check.md`に記録する。

## 実装方針

- `_segment_grid_traversal_accumulate`(`chatcarlo/tally.py:302`)のアルゴリズム(1本のレイと格子の交差を列挙し、各交差区間の重み×長さをkerma/H\*(10)グリッドへ加算)を読み、**同じ交差列挙ロジック**をnjitスカラー(1レイずつループ、prangeなし)で書き直す。既存のargsort/lexsortベースの一括処理ではなく、DDA(Digital Differential Analyzer)アルゴリズムそのもの(ボクセルを1つずつ辿る)で実装する — これが「カーネル内にnjitで再実装する」設計(a)の中身。
- シナリオの役割を分ける(元計画で`examples/chest_room.yaml`とwater60_freeを混同していた点の修正):
  - **正しさ**: 合成境界ケース(上記列挙)＋chest_room由来の複数方向区間集合
  - **主要速度ゲート**: water60_free(元の0.402秒と同一条件)のみ
  - **一般化確認**: chest_room(参考値)
- 過去に複数回バグを踏んだ領域なので、正しさの検証(ボクセル単位)を速度測定より先に必ず終わらせること。
- 単一レイで境界ケースを確認し、その後複数レイ(water60_free N=2e5・chest_room由来)で集計値を突き合わせる、の2段階で進める。

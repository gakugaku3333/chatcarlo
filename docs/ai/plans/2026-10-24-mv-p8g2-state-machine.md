## 1. 目的（この計画が答える問い）

P8g-1 の積層の核（T4、40×256・20 万履歴で 198.4 µs/履歴）の **1 履歴を完走する形**を、水の核で効いた **段階ごとの状態機械（P5g 型）と、レーンごとの補充（P5k の変種 F 型）** に書き換えたとき、
(a) 結果が P8g-1 と**履歴ごとにバイト一致**したまま、(b) T4 で何倍速くなるか。

- ユーザーの決定（2026-10-24）: 「B の計画に進めて」。順番 A1 → B → A2、ビット一致に縛られない検証（費用のかからないところでは一致を使う）。
- 水の核の前例: P5g（状態機械）は V0 と履歴ごとにバイト一致したまま ×1.87、P5k F（補充）は P5j とバイト一致したまま ×1.83。どちらも物理・乱数の消費順・演算を変えず、**実行の順番だけ**を変えた。B も同じく、各履歴の計算は変えない。したがってバイト一致を**関門で確かめる仮説**とし、合格すれば P8f の判定 A・B の合格を引き継ぐ（新しい本計算と EGS5 との検定はしない）。
- 速さの見込みは書かない（mv.md「命令数・レーン数・模擬から速さを順位づけしない」。P5h/P5k/P5l で予測が逆になった）。T4 の実測で決める。

## 2. 前提事実（検証済み、2026-10-24）

- P8g-1 は合格・implemented（`docs/validation/mv/p8g1/RESULTS.md`）。T4 の µs/履歴（中央値）: P8g-1 40×128 で 262.0（2 万）・221.1（20 万）、40×256 で 243.1・198.4。資源: 234 レジスタ、ローカル 34,112 B、常駐ブロック/SM は 128 スレッドで 2、256 で 1。

- `p8g_history`（`p8g_kernel.h:50`）の形は水の V0（`p5_kernel.h` の `history`）と同じ: `while(top>=0)` でスタックから 1 粒子を取り出し、光子なら 1 回の相互作用（蛍光・緩和で二次粒子を積む）、荷電粒子なら `for(;;)` のステップのループ（`continue` で次のステップ、`break` で終わり）、その後の後始末（`p8g_kernel.h:230` 以降: 陽電子の消滅など）。失敗（`steps>maxsteps`、スタックのあふれ）は `failed` で外のループを抜ける。
- P5g の段階: `P5G_P`（取り出しと光子）、`P5G_C`（荷電粒子の 1 ステップ）、`P5G_E`（荷電粒子の後始末）、`P5G_H`（履歴の終わり）、`P5G_D`（完了）。`p5j_kernel.h:141` の `P5jPhase` も同じ 5 つ。
- P5k F（`p5k_gpu.cu:54` の `variant==0`）: 状態はレーンの局所に持つ。毎回ワープで段階ごとに `__ballot_sync` を取り、段階の順に該当レーンが 1 遷移ずつ進む。完了したレーンはその場で出力して `atomicAdd(next,1)` で次の履歴を取る。ブロック全体の詰め直し（Q 系）は同期待ちで F より遅かった（P5k RESULTS）。
- P8g-1 の出力の経路: 履歴ごとの記録 `P8gRecord`（double 1,200・整数 1,200）を `p8g_record_history` で作り、群へ atomic で足す（`p8g_gpu.cu`）。
- 比較の道具: `p8g_core.exact_histories`（全出力のバイト比較）、`check_records`（群の集計と履歴の和、加算の上限つき）、P8f の保存参照（`~/.cache/chatcarlo/p8f_prof/p8f/export/`）。

## 3. 設計

### D1. 段階の分け方（P5g と同じ 5 段階）
- `P`: スタックから 1 粒子を取り出す。光子なら P8g-1 と同じ 1 回の飛行と相互作用まで行い、`P` に戻る。荷電粒子なら初期化して `C` へ。
- `C`: 荷電粒子の**ステップ 1 回**（P8g-1 の `for(;;)` の本体 1 周）。`continue` に当たるところは `C` のまま、`break` に当たるところは `E` へ。
- `E`: 荷電粒子の後始末（`p8g_kernel.h:230` 以降の処理）。終われば `P`。
- `H`: 履歴の終わり（失敗を含む）。記録の確定と出力。
- `D`: 完了（次の履歴を待つ）。
- 段階をまたいで残る局所変数（`failed`、`suspended`、`annihilated`、`steps`、`top`、ステップのループ内で前の周の値を使う変数など）は、**すべて状態の構造体に移す**。実装者は P8g-1 のループの局所変数を一覧にし、各変数を「状態に移す／各段階の中で毎回作る」に分けて `docs/validation/mv/p8g2/state_variables.md` に理由とともに残す。
- 乱数の消費順・演算・物理は P8g-1 のまま。遷移の関数は P8g-1 のループの本体を写し、`continue`/`break` を段階の代入に置き換えるだけにする。

### D2. 実行の形（P5k F と同じ）
- 状態はレーンの局所に持つ。ワープで段階ごとに `__ballot_sync`、段階の順（`P`→`C`→`E`→`H`）に、その段階のレーンが 1 遷移ずつ進む。`C` も 1 遷移（K=1）。
- 完了したレーンは、P8g-1 と同じ `P8gRecord` で群に足し（または履歴ごとの出力に書き）、`atomicAdd(next,1)` で次の履歴を取って初期化する。履歴の番号と乱数の初期化は P8g-1 と同じ（種と履歴番号）。
- CPU 版は同じ遷移の関数を、1 履歴ずつ段階が `D` になるまで回す（逐次の等価物）。さらに CPU で「複数のスロットを段階ごとに順番に進める」模擬の駆動を持ち、遷移の途中で別の履歴に切り替わっても結果が変わらないこと（状態の漏れがないこと）を手元で確かめる。
- 起動の大きさは引数（ブロック数・スレッド数）。

### D3. 新しいファイル（P8g-1・P8f・P5 のファイルは編集しない）
- `p8g2_kernel.h`（状態の構造体と遷移の関数。P8g-1 の `p8g_*` の関数・表の定数 log の読み出しを `#include` して使う）、`p8g2_cpu.cpp`、`p8g2_gpu.cu`、`p8g2_core.py`、`p8g2.py`、`p8g2_colab.py`、`p8g2_cli/`、テスト `test_p8g2*.py`。

## 10. Codex レビュー 1 巡の反映（§3〜§9 と食い違うときはこちらが優先）

**10.1 遷移の対応表（指摘 1）。** 遷移を次に固定する。置き換えるのは `p8g_history` の外側の `while(top>=0)` と荷電粒子の `for(;;)` の `continue`/`break` だけで、P の中の光子が層を横断する `for(;;)` と緩和の内部のループの `break`/`continue` は P の中に残す（段階の終わりではない）。実装者は対象の `break`/`continue` の全箇所を行番号つきで `state_variables.md` に対応づける。

| 元の終了理由 | 遷移と保持事項 |
|---|---|
| P の中の上限・容量の失敗 | `P→H`。取り出した現在の粒子と残りのスタックを保持 |
| スタックが空 | `P→H` |
| C の中の失敗 | `C→H`。E を実行しない（元は `if(failed)break;` で後始末を飛ばす） |
| C の正常な終了・親粒子の退避 | `C→E` |
| E の中の消滅光子のための容量不足 | `E→H` |

失敗した位置までの更新の順も仕様とする（硬衝突の容量失敗での `a[6]+=W`、制動放射の容量失敗で既に足した `brems` を残す等）。H の `unresolved` は現在の粒子に続いてスタックを添え字順に足す。P の光電効果の処理（緩和の乱数消費、`top+used+2` の検査、局所の付与、放出光子の順の push、最後の光電子の push）は一まとまりで P に保持し、分割しない（P5g の光電の処理に置き換えない）。

**10.2 状態の棚卸しと寿命（指摘 2・10・11）。**
- 一覧の対象は `p8g_history` の局所変数に加え、呼び出し側の `P8gRecord`、`P8gOutput.maxdepth`、`P5Diagnostic.used/overflow`、乱数の状態、各ポインタの寿命。
- 状態に持つのは**遷移をまたぐ値だけ**。`m`/`t`、係数の密度換算値、光子の飛行途中の変数、緩和の一時配列は P または C の中で毎回作る。短命な局所オブジェクトへのポインタ（`a`、`t`、`P8gOutput` など）を次の遷移へ持ち越さない。`m` を作り直すときは `t=&m.p` も同じ段階の中で結び直す。
- `cached_ev` と係数群、`suspended`・`annihilated` は荷電粒子を取り出すときに初期化し、C の各周では保持する。材料の境界では元どおり `cached_ev=-1`。
- 責任の分担: **H は輸送の結果の確定（収支・最大値・各集計のあとに `source/dep/calls/diag.used/maxdepth/nspec_index/additions` を記録へ確定）と `D` への遷移だけ**。駆動側が `D` を検出して「書き出し → 局所の配列と記録を消す → 次の履歴の初期化」を 1 回だけ行う（P5k と同じ）。
- 補充のたびのゼロ化は、出力・キャッシュ・管理値と診断が読む値に限り、スタックは push のときに書く（全体のゼロ化をしない）。ゼロ化する範囲は `state_variables.md` に書く。
- CPU は 2 つの出力の経路を持つ: 履歴の比較では局所の記録へ書き、保存バッチとの比較（1a）では**同じ遷移から共有の出力へ直接足す**（記録の後からの合算にしない。`brems[1]` の加算順のため）。

**10.3 F 型の駆動の契約（指摘 4）。** 周回の冒頭で全レーンの段階を snapshot し、段階ごとのマスクを**仕事の前にすべて確定**する（P5k F、`p5k_gpu.cu:60`）。各段階の直前に取り直さない。無効・完了したレーンもワープが終わるまで集合演算に参加する。補充した履歴は次の周回から進める。初回の履歴の取得は P5k F と同じく `atomicAdd(next,1)`、`next` の初期値は 0。CPU の模擬も同じ snapshot の規則と**実際のスロットの再利用**（スロット数 32・64 で全 20,000 履歴を流す）を使う。

**10.4 必須の経路と比較の手段（指摘 3）。** CPU と T4 の両方で、到達の証拠を持つ固定例を用意し、**必須の経路に到達しなければ関門は未完了**とする（「0 の遷移は理由を記録」は廃止）:
複数の層を通る光子、低エネルギーの光子の局所吸収、緩和の光子を複数積む場合とその容量の判定で失敗する場合、硬衝突・制動放射の親粒子の退避と再取り出し、陽電子の停止時の消滅・飛行中の消滅・脱出、E での容量の失敗、異なる材料の境界の通過後のキャッシュの再計算、境界の散乱で元の領域に残る場合。
到達の証拠は分岐ごとの数え上げ（検査ビルド、グローバルメモリの数え上げ。mv.md）で示す。小さい `maxsteps`・小さいスタック容量の比較のために、新規の `p8g2*` 側に、凍結した `p8g_record_history` を任意の上限・容量で呼ぶ参照のラッパー（CPU・GPU）を作る（P8g-1 の `p8g_histories` と GPU の核は `maxsteps=10000000` 固定、GPU のラッパーは容量 16 未満を拒否するため）。

**10.5 集計の検査（指摘 5）。** 2c の照合は P8g-1 の `p8g_core.check_group_records`（生の 100 群を群ごとに検査）を使う。群への加算を 1 つ落とす故障（g4）と群の番号をずらす故障（g5）を足し、これが拒否することを確かめる。

**10.6 構成と経路の対応（指摘 6・8・9）。**
- 計時する 3 構成（40×128・40×256・80×128）すべてで、2b（同じ GPU の P8g-1 との履歴ごとのバイト一致）・2c（群ごとの集計）・出力回数・2d（その構成の総スロット数の直前・一致・直後）を行う。計時の `history=False` の経路は、履歴の比較の経路と同じ遷移・確定・加算の処理を使う。
- 新規の指紋（`p8g2_core.fingerprint()`）に遷移・駆動・出力の処理のファイルを入れ、束・スタック容量・コンパイルの指定・起動の条件を関門から計時の記録へ結ぶ（起動・測定のスクリプトは指紋に入れない）。GPU のスタック容量は P8g-1 と同じ 18（既定の 4096 を持ち込まない）。
- 資源の記録に共有メモリ・`max_threads_per_block`・実際のスタック容量を加え、ncu ではローカルメモリの読み書きと関連する待ちも確かめる。常駐ブロック数が同じでもローカルへの退避で遅くなりうるので、その場合も結果とともに報告する。レジスタの上限は導入しない。
- 倍率は「P8g-1 から B 全体への変更」と書く（P8g-1 はすでに完了後の補充をしているので、水の P5j→P5k F の ×1.83 を積層の追加の余地とは扱わない）。ウォームアップと表の初期化の時間は核の時間と分ける（A1 と同じ）。

**10.7 故障の注入の固定（指摘 7）。** 出力を確実に壊す対象と到達入力を固定する:
- g1: 飛行中の消滅のあとの `annihilated` を E で明示的に false に戻し、二重の消滅を起こす固定例（10.4 の陽電子の飛行中の消滅の例）→ 0b で拒否。
- g2: 再利用するスロットの `bins` を消さない。2 つの履歴を固定し、前の履歴の付与が次へ残る → 0c（実際のスロットの再利用）で拒否。
- g3a 完了した履歴を 2 回出力、g3b 1 つ飛ばす → 出力回数の検査でそれぞれ拒否（別々に記録）。
- g4・g5 は 10.5。未初期化にするだけの故障は再現できる検出の試験にならないので使わない。

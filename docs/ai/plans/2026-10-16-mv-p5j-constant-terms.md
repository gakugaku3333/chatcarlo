## 目的

P5i の核のエネルギー更新（`p5i_kernel.h:305〜309`、`ev!=cached_ev` のとき）で計算する次の3つを、**同じ端末の同じ関数で1回だけ計算した値**、または**同じ更新の中で1回だけ計算した値**に替える。各履歴の結果は P5i とビット単位で同じに保つ。速さは報告のみ。採否はユーザーが決める。

## 0. 前提事実（2026-10-16 に確認）

**P5i の倍精度の命令**（`p5i/results/map/P5i_profile/source.csv` を手元で集計。全 1.037e10、ワープ命令の 26.5%）: 対象の行の割合は、メラーの3行（`compiled.cu` 205・208・218）14.5%、阻止能の 195行 3.5%、`log(ev)` を含む3行（879・885・196）6.3%。インライン化で行の割り当てがあいまいなので、減る量は倍精度の命令の **約6〜14%**（単純化した仮定による試算。時間が倍精度の命令に比例するなら ×1.06〜1.16）。

**対象**（凍結した `p5_kernel.h`・`p5a0_common.h` と、P5i の `p5i_kernel.h` の中）:

| # | 場所 | 式 | 替え方 |
|---|---|---|---|
| A | `p5_hard`（`p5_kernel.h:44`）→ `p5_primitive0(.5,a,b)` | `log(x/(1-x))`、x=.5 | 端末ごとに `log(.5/(1-.5))` を1回計算した定数 |
| B | `p5_hard`（`:45`）→ `p5_primitive1(.5,a,b)` | `log(x)`、`log1p(-x)`、x=.5 | 端末ごとに `log(.5)`、`log1p(-.5)` を1回計算した定数 |
| C | `p5_collision`（`:20〜21`） | `log1p(-d/tau)`、`d=tau/2` | 端末ごとに `log1p(-.5)` を1回計算した定数。ただし `-d/tau==-0.5` を毎回確かめ、違えば元どおり計算する |
| D | エネルギー更新の `p5i_quantities(ev)` と `p5_collision(ev)` | `log(t>cut?t:cut)`、`log(t)`、`log(T)`（どれも引数は `ev`） | 更新の頭で `log(ev)` を1回計算して渡す。引数の値が `ev` と同じビットのときだけ使う |

- **C の確認**: T を 1e-3〜20 MeV で 1,000万個（対数一様）取り、`tau=T/M`、`d=tau/2` で `-d/tau==-0.5`・`tau-d==d`・`tau/(tau-d)==2` がすべて成り立った（NumPy、binary64）。理由: `tau/2` は正確、`(tau/2)/tau` は正確な 0.5 を丸めた値で 0.5。ただし入力が非正規数・0・無限大・NaN では成り立たない可能性があるので、C は毎回の確認つきにする（元の式と同じ値になる経路だけ定数を使う）。
- A と B は、引数が字句の定数 `.5`。`1/.5`、`1/(1-.5)` はコンパイラがすでに畳んでいるかもしれないが、今回は替えない（`log` 系だけを替える）。
- D: `quantities` の `log(t>cut?t:cut)` は `ev>.01` のとき `log(ev)`。`ev` は `p5_max(.01,a[7])` なので `ev>=.01`。`ev==.01` でも `t>cut?t:cut` は `.01`（同じビット）。どちらでも引数は `ev` と同じビットになるが、実装では引数のビットが `ev` と同じかを確かめる形にしてよい（詳細は実装）。
- 凍結: `p5_kernel.h`・`p5a0_common.h`・`p5g_*`・`p5h_*`・`p5i_*` は変えない。

**ビット一致の根拠**（P5i と同じ）: 同じ構成（M3・clang++ `-ffp-contract=off`、T4・NVRTC `--fmad=false`）の中で、同じ翻訳単位・同じ指定で、同じ引数のビットに同じ関数を当てれば同じ値。式の変形（`log(a/b)`→`log(a)-log(b)` など）はしない。定数を使った後の式は、元の式の演算の順番を字句まで保つ（例: `a*x-1/x+1/(1-x)-b*K0`）。

## 1. やり方

- 新規 `p5j_*`。P5i の遷移の関数から A〜D に届く関数（`p5_hard`・`p5_primitive0/1`・`p5_collision`・`p5i_quantities` と、それらを呼ぶ P5i の関数）を、呼び出しの経路ごとに `p5j_` の名前でコピーし、対象の部分だけを替える（P5i の §6・§7 と同じ作り方）。
- 定数 K0=`log(.5/(1-.5))`、K1=`log(.5)`、K2=`log1p(-.5)` は、P5i の対数の配列と同じ初期化（CPU は駆動の初期化、GPU は初期化の核）で、元の関数と同じ翻訳単位・同じ指定で1回計算する。
- D は、エネルギー更新の頭で `Lev=log(ev)` を1回計算し、`p5j_quantities` と `p5j_collision` に引数で渡す。他の場所から呼ばれる `quantities`（`p5i_sample_k`、制動放射の後）は今までどおり自分で計算する。

## 2. 関門（測る前に固定。P5i と同じ形）

0. **関門0**（CPU と T4）: 正式な条件は、凍結した元の関数（`p5_hard`・`p5_collision`・P5i の `p5i_quantities`）と新しい関数の**全出力のビット一致**。入力は 0.01〜20 MeV の格子点・その `nextafter` の両隣・`.02`（`p5_hard` の境）と `.5-x<1e-7` の境の両隣・乱数 100万個、加えて C の確認が働く入力（0、非正規数、無限大、NaN。元の関数が定義される範囲で出力を比べ、定義されない入力は「確認で元の式に戻った」ことを数える）。K0〜K2 の値と、元の式をその場で計算した値の比較は補助の診断。
1. **関門1**（手元、M3）: 新しい CPU ビルドが、保存済みの P5a Philox 100バッチとバイト一致（通常版・検査版）。検査版で、A〜D が通った回数と、C で元の式に戻った回数を数える（A〜D それぞれ 0 でないこと）。
2. **関門2**（T4）: 指定の2万履歴で、履歴ごとの全出力が P5i と `core.bits` で一致（通常版・検査版）。通った回数の条件は関門1と同じ。
3. **関門3**（T4）: P5c の C0〜C4（1,000万履歴）。指紋に `nspec=20`。
- 順番: CPU 関門0 → 関門1 → T4 関門0 → 関門2 → 関門3。
- **速さ**（報告のみ）: 同じセッションで P5i と P5j を交互に3回ずつ。初期化の時間を分けて出す。
- **地図**（報告のみ）: P5i と P5j の両方で ncu の生の記録（`.ncu-rep`・`source.csv`）を取る。一方が失敗しても、もう一方を取る。集計は Claude が手元で。全命令・倍精度の命令・レジスタとローカルメモリ・時間を並べる。命令の数だけで結論しない。
- 判定の記録の指紋は計算のファイルだけ（生成した定数・配列のハッシュは含める）。Colab は「すべてのセルを実行」1回、ソースは Drive の zip。

## 6. 1巡目の反映（§1〜§5 と食い違うときは本節が優先）

1. **一致の主張**: 「すべての入力で一致」とは言わない。言えるのは「固定した構成で、関門0の入力と、関門1〜3の輸送で一致した」こと。判定は**通常版・検査版それぞれの最終の関数の出力**で行い、元の版にコンパイルの指定を足して比べない（凍結した構成のまま比べる）。元の `p5_hard` の中で定数がすでに畳まれていて、配列から読む値と違えば、関門0か1で不一致として現れる（その場合は停止して報告）。
2. **C の書き方を固定**: `double arg=-d/tau; double L=(arg==-0.5)?K2:log1p(arg);`。`-d/tau` の字句はそのまま。`tau-d`・`tau/(tau-d)` は替えない。許容差つきの比較は使わない。
3. **D の契約**: 新しい関数は `(Lsrc, Lval)` を受け取り、各 `log` の**実際の引数**が `Lsrc` と同じビット（`memcpy` で比べる。NaN・符号付きゼロも区別）なら `Lval` を使い、違えば元の `log` を計算する。`Lsrc` が NaN なら使わない。`disabled`・`t<=cut` の早い `return` は元の位置のまま。エネルギー更新の頭で `Lsrc=ev`、`Lval=log(ev)`。
4. **特殊な入力**: 関数の全出力の比較は、元の関数が配列の範囲の外を読まない入力に限る（NaN を `interp` に渡さない）。C の分岐は、`arg` の計算と分岐だけを取り出した検査で、0・±0・非正規数（成り立つもの・成り立たないもの）・±∞・NaN を調べる。NaN の出力は `core.bits`（符号と payload まで）で比べる。
5. **静的な検査**: 「元の式が残っていない」ではなく、「指定した呼び出しの位置だけが替わり、C・D の戻りの経路と、対象外の経路（下端 `x=.01/T` の原始関数、`sample_k`、制動放射の後の `quantities`）には元の式が残っている」ことを検査する。原始関数全体は定数にしない。A では `K0` が 0 でも `-b*K0` を消さない。B の項は結合・並べ替えをしない。
6. **関門0の構成**: CPU・T4 とも通常版と検査版の両方。数え上げは場所ごと: A、B の2つ（`log(.5)`・`log1p(-.5)`）、C の定数と戻り、D の3か所それぞれの再利用と戻り。入力: `cut` の直前・同じ・直後、`disabled` の両方、`.02` と `.5-x<1e-7` が切り替わる隣の binary64、0.01〜20 MeV の格子点とその両隣、乱数 100万個。`quantities` は4つの出力に加えて、低水準の関数の `idx`・`raw` の全要素も比べる。通常の輸送で C の戻りが 0 回なのは問題ない（関門0で通ることを求める）。
7. **比較の先と指紋**: 比較の基準（`baseline`）は **P5i**（P5g ではない）。関門2・速さ・地図の比較の先が P5i であることをテストで確かめる。指紋には K0〜K2 と、引き継いだ対数の配列の**実際の値のハッシュ**（端末で作った値をホストに取り出して計算）を入れ、関門の記録と途中保存の再開の照合に使う。関門0の合格の記録も後の関門で確かめる。
8. **停止**: CPU の関門0か関門1が不一致 → GPU に進まない。T4 の関門0が不一致 → 関門2・3・速さに進まず、採用しないと記録する。

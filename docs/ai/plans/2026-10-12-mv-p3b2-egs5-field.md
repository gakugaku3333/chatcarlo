## 目的

[P3bの骨子](2026-10-12-mv-p3b-field-pdd-ocr.md) の第2段階。`p3r_egs.f` の写しに、(1) 水面で10×10 cm²・線源から100 cmの発散の線源、(2) [P3b-1](2026-10-12-mv-p3b1-prototype-kernel.md) の試作と**同じ領域・同じ按分の規則**の集計、を足す。EGS5の物理・カットオフ・乱数の設定は変えない。P3b-3（試し計算と本番）で、両コードの出力を1つのPythonの関数で同じ量に直せる状態にする。

## 0. 前提事実（検証済み。2026-10-12に確認）

- **荷電粒子の1歩は直線で、集計の呼び出しは移動の前**（`docs/egs5_crosscheck/egs5/egs/egs5_electr.f`）: 256〜257行 `ustep = ustep0` / `edep = 0.d0` → 266行 `if (ustep .gt. dnear(np)) call howfar` → 317行 `if(medium.ne.0) edep = ustep * dedx`（`howfar` が歩を切ったあとの長さで計算）→ 322行 `call ausgab(0)` → 327〜329行 `x(np) = x(np) + u(np)*ustep`（y、zも同じ）。向きの変更（多重散乱の折れ点）はそのあとの別の処理。したがって `ausgab(0)` の時点で、沈着の線分は `(x,y,z)` から `(x,y,z)+(u,v,w)*ustep`。試作の検査B5b（折れ点の前の向きで線分を記録）と同じ対応。
- 光子も同じ順序（`egs5_photon.f` 135行 `howfar` → 146行 `ausgab(0)` → 151〜153行で移動）。現行コードは光子の `iarg=0` では集計しない（`iq(np).ne.0` の条件）。
- `subroutine shower(iqi,ei,xi,yi,zi,ui,vi,wi,iri,wti)`（`egs5_shower.f` 7行）。現行の呼び出しは `shower(0,ehist,0.d0,0.d0,0.d0,0.d0,0.d0,1.d0,2,1.d0)`（`p3r_egs.f` 204行）。
- 現行の集計（`p3r_egs.f`）: 345〜350行が荷電粒子の歩（`z0=z(np); z1=z0+w(np)*ustep; loss=edep*wt(np)` を `p2segment` で深さへ按分）、351〜354行が点の沈着（`iarg.le.4` かつ `ir(np).eq.2`）、341〜344行 `iarg.eq.3` は領域の外へ出た粒子で、沈着ではなく流出に数える。区切りは0.2 cm（150区画）と0.05 cm（600区画）の固定。
- `howfar` は板の2つの面だけを見る（横は無限）。`dnear` は設定していないので毎歩 `howfar` が呼ばれる。
- 再開: 1バッチ（`ncase/100` 履歴）ごとに、乱数の状態（`rluxout`）と全部の集計を `checkpoint.bin` に書く（236〜248行）。`stop_batches.dat` があると、そのバッチで止まる（256行）。
- 線源のエネルギーは履歴の最初に乱数2個（186〜187行）。
- 出力はテキストの `egs5job.out`。`BATCH`・`FINE` の行は `ncase/100*区切り` で割ってある（288・292行）。`run_p3a.parse_egs` がタグごとに読む。
- 起動は `run_p3r.run_egs`（234行〜）。ファイル名 `p3r_egs.f` が書き込まれていて、`run_p3r.py` はハッシュで凍結されている（書き換え不可）。
- **試作の領域の出力は、バッチごとのエネルギーの和（MeV）そのまま**（`photon_transport_p3b.py` 184行 `region_scores`、455〜465行。体積・粒子数で割っていない）。領域の並びは `expand_regions`（468行）: 0 = 軸の直方体（粗）、1 = 同（細）、2 = 板全体、3〜 = 側方分布（粗→細、その中でx→y、その中で深さの順）。本番の `REGIONS=[0,0,1,1,9,.25,.125,1,5,10,20]` で15個、最大の区画数は300（軸の0.1 cm）、側方は72（0.25 cm）と144（0.125 cm）。
- 試作の履歴ごとの検査（435〜436行）: 板全体の箱は `|和−沈着| ≤ 1e-9×入射エネルギー`、他の箱は `和 ≤ 沈着+1e-9×入射エネルギー`。
- 按分の規則は `scoring_p3b.py`（半開の箱 `lo ≤ p < hi`、線分はパラメータ区間 `[t0,t1]` で切り、損失は元の線分に対する長さの割合）。解析解の表は `tests/test_p3b1.py` の `GEOMETRY`（136行）と点の表（167行）。

## 実装方針

### 1. `p3b_egs.f`・`p3b_egs_common.inc`（`p3r_egs.f` の写しに、次だけを足す）

- **既存の処理は1行も変えない**: 0.2 cm・0.05 cmの深さの集計（`score`・`fine`・`p2segment`・`p2point`）、収支、タグ、乱数の初期化、PEGSの設定、カットオフ。
- `field.dat`（1行: `field_half ssd`）があるときだけ発散の線源。エネルギーの乱数2個のあとに乱数を2個引き、`xs=(2*r1-1)*field_half`、`ys=(2*r2-1)*field_half`、`norm=sqrt(xs*xs+ys*ys+ssd*ssd)`、`shower(0,ehist,xs,ys,0.d0,xs/norm,ys/norm,ssd/norm,2,1.d0)`。ないときは現行の呼び出しそのまま（乱数の消費も同じ）。値が有限でない・正でないときは `stop`。
- `regions.dat` があるときだけ領域の集計。**箱の並びをFortranで作り直さない**: Pythonが `expand_regions` の結果をそのまま書く（1行目に箱の数、以後1箱1行で `lo(3) hi(3) axis origin width size`、`%.17g`、axisは1〜3）。上限は箱16個・区画320。超えたら `stop`。
- `ausgab`: 既存の2つの沈着の分岐に、領域の呼び出しを足すだけ。歩は `p0=(x,y,z)`、`p1=p0+(u,v,w)*ustep`（深さは既存の `z1` と同じ式）。点は `(x,y,z)`。`iarg.eq.3` には足さない。
- 領域の配列はバッチに直接足す（`rbatch(320,16,100)`、MeV）。履歴ごとに箱ごとの和 `rsum(16)` を持ち、試作と同じ規則（前提事実）で違反を数える（`rledger(16)`）。
- 線源の観測: 最初の1,000履歴の `x y u v w` を保存し、全履歴の入射点を10×10のます（1 cm角）に数える。**実際に `shower` に渡した値を記録する**（別の式で作り直さない）。
- 再開: 足した配列・カウンタ（`rbatch`、`rledger`、入射点のます、最初の1,000履歴の記録）を `checkpoint.bin` の書き込みと読み込みの**両方**に足す。
- 出力（`egs5job.out` に足す）: `FIELD`（有無と2つの値）、`NREG`、`REGION 箱 lo hi axis origin width size`（読んだ値の確認用）、`REG バッチ 箱 区画 値`（**MeVそのまま。割らない**）、`RLEDGER 箱 違反の数`、`SRCHIST`、`SRC`。既存の行は順序も内容も変えない。

### 2. `p3b_egs_score.inc`（按分の部品）と `p3b_score_driver.f`

- `scoring_p3b.py` の `clip`・`score_box_point`・`score_box_bins` と、`photon_transport_p3b.py` の `deposit_segment`・`deposit_point` の箱のループを、同じ規則でFortranに写す（半開の箱、同じ早期の打ち切り、点への近道は両端が完全に等しいときだけ）。EGS5の共通ブロックに依存させない（引数だけで動く）。
- `p3b_egs.f` はこのファイルを `include` する。`p3b_score_driver.f` も同じファイルを `include` し、`regions.dat` と `segments.dat`（1行: `p0(3) p1(3) loss`）を読んで、箱ごとの区画の値を17桁で書く。**検査するのは、EGS5の中で実際に動くのと同じソース**（写しを検査しない）。ドライバは `gfortran` だけでビルドできる（EGS5は不要）。

### 3. `run_p3b2.py`

- `run_egs(name,N,seed,edges,cum,field=None,regions=None,stop_after=None)`: `run_p3r.run_egs` を写して、ファイル名、`field.dat`・`regions.dat` の書き込みと一致の確認、`config.json` への `field`・`regions`・追加したソースのハッシュの記録を足す。補助の関数（`job_lock`、`verify_config`、`egs_hashes`、`spectrum_text` など）は import して使う。作業場所は `CHATCARLO_P3B_CACHE`（既定 `~/.cache/chatcarlo/p3b`）の下の `egs5/`。
- 読み取り: 既存の `parse_egs` の検査に加えて、領域の行を読み、**試作と同じ名前・同じ形**（`axis_coarse (100,120)`、`axis_fine (100,300)`、`slab_coarse (100,120)`、`profile (100,2,3,72)`、`profile_fine (100,2,3,144)`、`region_ledger`）に並べ直して `result.npz` に保存する。`REGION` の行が、渡した `expand_regions` の値と完全に一致することを確かめる。
- 検査E1〜E6を固定の順に実行し、`checks_p3b2.json` に書く。結果のファイルか作業場所がすでにあれば実行を拒否する（やり直しをしない）。どれかが不合格なら、そこで止めて記録する。種は下の表の固定値で、変えない。
- EGS5の計算は1つずつ順に実行する（同時に2つまで、の規則の内側）。

## 詳細レビューの反映（上の記述と食い違う場合は、この節が優先）

1. **設定の照合はP3b側に持つ**: `run_p3r.verify_config` は定義元の `source_hashes()` を見るので再利用しない。`run_p3b2.py` に短い照合の関数と自分のハッシュ一覧（`p3b_egs.f`、`p3b_egs_common.inc`、`p3b_egs_score.inc`、`p3b_egs_ausgab.inc`、2つのドライバ、`run_p3b2.py`、`p3r_egs.f`、`p3r_egs_common.inc`、P3b-1の3ファイル、`run_p3r.py`）を持つ。`job_lock`、保存、スペクトルの処理、`egs_hashes` は import して使う。
2. **既存の出力は `run_p3r.parse_egs`（145行）で読む**（前提事実の `run_p3a.parse_egs` は誤り。P3aの検査は制動放射の生成数＝廃棄数を要求し、P3rでは通らない）。新しいタグは既存の読み取りに無視されるので、その結果に領域と線源の記録を足す。既存の読み取りを写さない。
3. **新規・再開・やり直しの禁止を区別する**: 新規の開始は、既存の作業場所を拒否する。再開は、同じ設定で正常な `checkpoint.bin` がある場合だけ許す（E5はこれを使う）。`checks_p3b2.json` に不合格の記録があれば、どの実行も拒否する。`stop_batches.dat` は残したままでよい（41バッチ目から再開すれば同じ所で止まらない）。
4. **「完全に等しい」の対象を列挙する**: E1とE5は同じ比較の関数を使う。対象は、深さ2種、収支（`totals`）、呼び出しの数、スペクトルの数、バッチごとの値、領域5種、`region_ledger`、線源の記録と入射点のます。`seconds`・`WALL`・`CPU` は除く。
5. **追加した行の読み取りは、不正を拒否する**: `REG` は、各バッチ・各箱・有効な区画にちょうど1行（欠落、重複、範囲外、列数の違いを拒否）。`FIELD`・`NREG`・`REGION` は設定と完全に一致し、余分な箱がない。沈着は有限で0以上、数は0以上の整数。`SRC` の件数と履歴番号、`SRCHIST` の100ますがそろっている。`REGION` の境界の無限大だけは許す。`regions=None`／`field=None` のときに `regions.dat`／`field.dat` が残っていれば拒否。これらの不正な文字列ごとの単体試験を入れる。
6. **E2cを直す**: x方向の3分割ではyの範囲を無限に、y方向の3分割ではxの範囲を無限にする（各3箱が板全体を覆う）。加えて、x・yそれぞれ「外・中・外」の9箱（中央が軸の直方体）で、9箱の和が板全体に、中央の箱が軸の直方体の値に一致することを確かめる。許容値は同じ。
7. **`ausgab` の接続の検査（E2d）を足す**: `ausgab` と `howfar` を `p3b_egs_ausgab.inc` に置き、`p3b_egs.f` がそれを `include` する。`p3b_ausgab_driver.f` は同じファイルを `include` し、EGS5の共通ブロック（`egs5_h.f`・`egs5_epcont.f`・`egs5_stack.f` を `-I` で参照。EGS5本体とはリンクしない）に値を直接入れて `ausgab(iarg)` を呼ぶ。場合は固定の表: 原点でなく重みが1でない（`wt=0.5`）荷電粒子の斜めの歩、横だけの歩、板の面で切られた歩、`iarg` 1・2・4 の点（面の上の点 z=0 を含む）、`iarg=3`（流出に数え、領域に入らない）、光子の `iarg=0`（何も入らない）、`iarg` 27〜30（何も入らない）。期待値は手計算の箱の寄与で、差 `1e-12` 以下。xとyの取り違えを検出するため、xとyで箱の大きさが違う領域を使う。
8. **`checkpoint.bin` の先頭に照合用のレコードを置く**: 形式の名前と版、`ncase`、`seed`、照射野の有無と2つの値、箱の数と各箱の値。読み込みで照合し、違えば `stop`。`done` が0より大きく `ncase` 以下で `ncase/100` の倍数であること、読み込みの失敗（`iostat`）も検査する。tmp→rename の書き方は変えない。設定・ソースを変えた再開の拒否は、**EGS5のプロセスを起動する前に**起きることを単体試験で確かめる（起動の関数を差し替えて、呼ばれないことを見る）。
9. **E1(a) もP3bの作業場所・出力場所で走らせる**: `run_egs` に、使うユーザーコード（`p3r_egs` か `p3b_egs`）を選ぶ引数を持たせる。`run_p3r.run_egs` は呼ばない（P3rの出力の場所に書いてしまうため）。
10. **「1行も変えない」の言い直し**: 既存の物理・既存の集計の演算・乱数の順序を保つ。許す変更は、`include` の名前、線源の呼び出し、`checkpoint.bin` の読み書き、`ausgab` の2つの分岐への領域の呼び出しの追加、出力の行の追加、だけ。削除の禁止は「新しく書くコードと手順に削除の命令を足さない」の意味（既存の `egs5run` の中の `rm` は対象外で、ビルドには今までどおり使う）。
11. **点の解析解の表の取り出し方**: `test_p3b1.test_b4_points` の `pytestmark`（`parametrize` の印）から場合を取り出す小さな関数を `test_p3b2.py` に置き、件数が0でないことと、取り出した件数を固定値で確かめる。既存のファイルは変えない。
12. **前提事実の訂正**: 光子の `iarg=0` は、荷電粒子の分岐を通らず、点の沈着の分岐で `edep=0` を足す（結果は同じ）。`iarg=3` は「利用者の指示による廃棄」で、現行の `howfar` が水の外で廃棄するので流出になる。`howfar` は `ustep > dnear` のときに呼ばれる（`dnear` を設定していないので実際には毎歩）。**`iarg` 27・28（エネルギーの折れ点）の `edep` は沈着に数えない**（現行どおり `iausfl` を立てない）。
13. 直線の区間への一様な按分は、この集計の量の定義である（曲がった実際の軌跡の再現を主張しない）。

## 停止条件

- E1〜E5のどれかが不合格なら、そこで止めて記録し、P3b-3に進まない。条件・種・粒子数を、結果を見たあとで変えない。
- EGS5のビルドが通らない、作業場所に書けない、などで検査を実行できなかった場合は、「未実行」と報告する（合格と書かない）。

## 書かなかったこと

- 位置の受け継ぎの検査（入射点と領域を一緒にずらす）は入れない: EGS5はもともと全粒子の位置を3次元で運んでいて、この段階で足すのは集計と線源だけ。
- 対称性と、試作との線量の比較は、P3b-3の試し計算で、検出したい偏りの大きさから粒子数を決めて行う（P3b-1のB8の教訓）。
- EGS5を2プロセスで走らせる仕組みは作らない。必要なら、種を変えた独立の実行を2本並べて、バッチをつなぐ（P3b-3で決める）。

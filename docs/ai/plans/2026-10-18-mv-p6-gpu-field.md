## 1. 目的（この計画が答える問い）

1. P5k F（GPU の合格構成、板の深さ線量だけ）を、P3b の照射野（発散する 10×10 cm² の線源、全粒子の xyz、領域への線分按分）まで広げられるか。
2. 広げた GPU の核が P3b の Numba の核と同じ計算をしていることを、P5 と同じ検証の鎖で示せるか。
3. GPU の計算で P3b-3 の 11 量（事前に決めた量と許容）が EGS5 と合うか。照合には保存済みの EGS5 の結果を使い、EGS5 を新しく回さない。
4. 速度は報告だけ（目標値は置かない）。

物理は変えない（カットオフ 10 keV、陽電子専用の物理なし、制動放射の光子を運ぶ、ステップの規則は P3s）。

## 2. 中心になる設計の判断

ユーザーの決定（2026-10-18）: D1 は案A、鎖1 は「兼ねる」。

### D1. どの核から広げるか

- **案A（推奨）**: P5j の遷移を写した新しいファイル（`p6_*`）に、発散線源（スペクトルの抽選のあと x、y の順に乱数を引く。P3b どおり）と、付与の箇所での採点の呼び出しだけを足す。既存の xyz 処理と物理の関数は再利用する。根拠は行数ではなく「線源・付与箇所・出力」の対応表（詳細計画で作る）。場なしでは P5k F とビットまで一致させる。
  - 利点: F の補充の方式を引き継ぐ（速度は引き継げない: 領域の配列は詰めても 1 履歴 14,688 バイト。実測する）。
  - 鎖0（MT）用には、P5j の CPU 入口（`p5j_cpu.cpp`）と同じく **MT の状態を持ったまま履歴を番号順に完走させる逐次の駆動**を別に置く。F の駆動は Philox 側だけで使う（F は履歴ごとに `rng_init` を呼ぶので MT では使えない）。
- 案B: P5a のような 1 履歴ずつ回す核で先に P3b を移し、そのあとで状態機械にする。二度手間になるので推奨しない。

### D2. 検証の鎖（P5 と同じ型）

- 鎖0（ビット）: C++ の CPU 版を MT19937 で回し、**保存済みの P3b-3 本番のバッチをバイトまで再現する**（P5a が P3r の本番バッチを再現したのと同じ方法）。全 15+6 個の出力すべて。数バッチ（例: 0 と 2）で行う。場なしでは P5k F の関門（保存済みの 100 バッチの Philox）とビットまで一致することも確かめる。
- 鎖1（統計）: C++ の CPU 版の Philox ↔ MT。違いは乱数だけ。
- 鎖2（履歴ごと）: C++ の CPU 版 ↔ T4 の GPU、同じ（種、履歴番号）で履歴ごとに比べる（P5 の関門2・3と同じ）。
- 最後: T4 で Philox 4,600 万履歴を回し、P3b-3 の 11 量で保存済みの EGS5 と比べる。判定の規則・許容・精度の条件は P3b-3 のものをそのまま使う（新しく決めない）。

鎖1 の扱い（ユーザーの判断）:
- **兼ねる（推奨）**: 最後の GPU の 4,600 万履歴を、保存済みの試作（MT）と保存済みの EGS5 の両方と比べる。計算は 1 回。ただしこの比較は「乱数の変更だけ」ではなく **CPU→GPU の移植全体の比較**と位置づけ、乱数の変更を分けて確かめたとは結論しない。先に領域つきの鎖2 を通す。
- 分ける: CPU の Philox で 4,600 万履歴を別に回す（P3b の Numba は M3 の 2 プロセスで 7,659 s。C++ は板で Numba の約半分だった（P5d: 122 対 257 µs）ので、約 1 時間の見込み。詳細計画で実測）。原因を切り分けやすいが計算が増える。

### D3. 採点の置き場

- 領域を切り出して付与量を求める関数は CPU と GPU で共通にし、足す先だけを切り替える。
- CPU の鎖0: P3b と同じく付与ごとに内部の 100 群へ直接加算し、最後に同じ順で縮約する（履歴内でまとめると加算の括り方が変わり、バイトで一致しない）。
- GPU: 履歴内の配列に足して履歴の終わりに atomic で合わせる（P5b の方式）か、付与ごとに直接 atomic で足すか（状態は小さくなるが atomic が増える）。詳細計画で決める。同じ付与列を両方へ流す小試験で、切り替えが正しいことを確かめる。
- P3b の `deposits`/`sources`（1 回ごとの付与の記録）は検査用。CPU の検査版だけに置き、GPU の本番版には置かない。

## 3. 事前登録の判定（骨子の段階）

- 鎖0: 指定したバッチで、全出力が保存済みのバッチとバイトまで一致する（`brems[1]` は P5b の注記のとおり、計算した範囲で一致すればよい）。
- 場なしの回帰: P5k F の関門1と同じ比較がビットまで一致する。
- 鎖2: P5 の関門2・3と同じ規則（履歴ごとの対の差で合否、一致した割合は報告だけ）を、**追加したすべての領域出力**（平均する前の符号つき・x/y 別の側方分布を含む）に広げる。atomic の集計との照合、非有限値の検査も同じ。11 量は方向を平均するので、左右や x/y の取り違えは鎖2 で落とす。
- 採点器の決定論的な試験: 境界の上、負の方向、箱の横断、点の付与。故障を入れた検出: 側方のビンをずらす、領域の付与を落とす、F の補充で配列を消し忘れる。
- 最後の照合: P3b-3 の 11 量、同じ許容（線量 1%、位置 0.1 cm）、同じ精度の条件（SEM 1/3%、0.033 cm）、同じ固定 `Dref`。別の乱数なので精度の条件に届く保証はない。届かなければ「統計不足」と記録し、履歴数を足すかどうかはユーザーが決める（基準は動かさない）。

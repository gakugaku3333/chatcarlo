## 目的

1. P5aの共通の核（`p5_kernel.h`、**編集しない**）をGPUで動かす薄い入口（CuPy RawKernel）、Colab用のノートブック、入力の束を作るスクリプトを用意する。
2. GPUで測る前に、**鎖2とP5cのすべての合否の基準を数値で固定する**（§3）。
3. 手元で、比べる道具が誤りを見つけること（わざと入れた誤りの検査）を、CPUのビルドを「相手側」の代わりにして確かめる。
4. GPUでコンパイルできることを、Colabで `compile()` を明示的に呼ぶセルだけで確かめる（P5bのColabの作業はこれだけ。実行はユーザー）。

P5cの実行は別の承認で行う。この計画はP5cの手順と基準を固定する。

## 0. 前提事実（検証済み、2026-10-14）

- **P5aのソースの指紋**（`CPU.identity` に入り、保存済みのPhiloxのバッチと鎖0の記録がこれに結び付く）: `p5_cpu.cpp` `11fd05ed…9a7f81`、`p5_kernel.h` `39d82e04…bd549`、`p5_rng.h` `6c325758…760f`、`p5a0_common.h` `8c209cfe…0c70c2`、`p5a.py` `2609e2a6…743934`。**P5bでこの5つを編集しない。**
- **`history()` は出力を素の `++`／`+=` で書く**（`nspec`、`counts`(16)、`brems`(10)、`totals`(6)、`violations`(3)、`maxima`(3、最大値)、`maxdepth`、`batches[batch*150+z]`、`fine_batches[batch*600+z]`、`step_batches[batch]`）。GPUで共有すると競合する。
- **`brems[1]` は履歴の途中で、制動放射の光子が出るたびに共有の出力へ足される**（`p5_kernel.h` 447行）。履歴ごとの局所の出力を後から足すと足す順が変わり、P5aとビットでは一致しない（Codexの実測: 2万履歴で 321.5457570755974 対 …971、差 −2.84×10⁻¹³ MeV）。ほかの出力は履歴の終わりに1回だけ足されるので、履歴の順に足せばビット一致する（同じ実測で `batches`・`totals` は完全一致）。
- **1履歴の作業量**: 核の局所変数（スタック `P5State[64]`、`hs[150]`、`fine[600]`）約17.8 KB ＋ 局所の出力 約11.7 KB ＝ 約30 KB（一時変数を除く）。平均ステップ 659.4。
- **履歴と行の対応**（`p5a.py` 574〜630行、`p5_cpu.cpp`）: Philoxの本番は種 `20291960`、バッチ `b`（0〜99）を1回の呼び出し `cpu.run(100000, 20291960, start=100000*b)` で計算し、`~/.cache/chatcarlo/p5/p5a/philox/batch_{b:03}.npz` に保存。呼び出しの中で履歴 `h` は行 `h*100/n` に入る。乱数は `rng_init(seed, start+h)` → 全体の履歴番号は `100000*b+h`。
- 保存済みの `config.json` に入力の25配列の sha256 がある。GPUに渡す束はこれと一致しなければならない。
- **`p5a.py` はモジュールの先頭で `physics` などを読み、`physics` は追跡されていない `estar.npz` と Numba を要る**。Colabの固定コミットには `estar.npz` がないので、Colab側で `p5a` を import できない。
- **ばらつき**（保存済みのPhilox 100バッチから計算。Codexが同じ値を再計算）: 深い5ブロックの1履歴あたりの標準偏差は `Dref` の 312.7／264.1／232.0／246.7／214.5%。1,000万履歴のSEMは 0.0989／0.0835／0.0734／0.0780／0.0678%。
- **わざと入れた誤りの事前の試算**（Codex、2万履歴、CPU同士）: F1 は健全性の違反0・最初の2ステップの乱数の回数の一致100%・同じ道の履歴のビン一致100%。F2 は健全性の違反387履歴（板の端で付与を失う）・ビン一致24.9%。F3 は乱数の回数の一致24.96%・健全性の違反0。
- `p5a_random` は入力の列全体で引いた回数を1個だけ返し、入力ごとの回数は返さない。`table_rates` は `log`/`exp`、`hard` は `log`/`log1p` を使う（数学関数を通る）。`sample_W` は数学関数を使わない。
- `P5Diagnostic.used` は容量を超えても全ステップ数まで増える（保存されるのは `min(used, 容量)` 件）。
- P5a0（Colab T4、CuPy 14.0.1、CUDA 13.0）: Philoxの整数列・実数への変換・原子的な加算は CPU↔GPUでビット一致。`--fmad=false` が効く。GPUの数学関数は入力の0.3〜27%で最後のビットが違う。受け渡しは gmail の Drive `MyDrive/viveMonte/p5/`（同期フォルダ経由）。

## 2. 設計

### 2-1. 共通の入口の関数（`p5b_wrap.h`）

- **1履歴**: `p5b_history(t, seed, global_h, maxsteps, L)`。`L`（`P5bLocal`）をすべて0にし、`P5Output` の各ポインタを `L` の配列に向けて **`batch=0`** で `history()` を呼ぶ。乱数は `rng_init(&s, seed, global_h)`。終わったら `L->calls = s.calls`。`L` は粗いビン150、細かいビン600、`totals` 6、`maxima` 3、`brems` 10、`violations` 3、`counts` 16、`nspec` の添字（核は `++o->nspec[j*10+cell]` と書くので、入口の中に0で初期化した書き込み用の `long long nspec_work[640]` を用意して `history()` に渡し、実行後に増えた1個の添字を取り出して1個の整数で持つ。入口で `nspec*10 ≤ 640` を確かめる。作業領域は約5 KB増える）、`steps`、`maxdepth`、`calls`、診断（容量4、各7値）と `min(used,4)`。
- **行**: `p5b_row(h, n) = int(h*100/n)`。P5aの `p5a_run` と同じ式・同じ整数の型（`int`、`h*100` があふれない範囲は入口で確かめる: `n ≤ 20,000,000`）。本番のカーネルと行の対応の検査が同じ関数を使う。
- **表の全フィールドの読み出し**: `P5Tables` の全ポインタの全要素を、そのまま出力の配列へ順に写す（各フィールドの要素数は寸法から計算）。スカラー（`bpar`、`delcm`、`delpos`）と寸法（`ne`…`nspec`）も写す。引数の並びの誤りを輸送の前に捕まえる。
- **関数の検査**: 入力 `j` ごとに乱数を `rng_init(seed, j)` で初期化し直し、`p5_collision`、`p5_hard`、`p5_coefficients`、`p5_table_rates`、`p5_sample_W`、`p5_gs_mu_cached`（`table_rates` の値を渡す）の値と、その入力で引いた乱数の回数を返す。CPUとGPUで同じ関数を使う。入力はP5aの A1 と同じ点（`p5a.energy_points` などで手元で作り、束に入れる）。
- **乱数の整数列**: `philox(seed, h, c)` の4語と実数を、指定の `(seed, h, c)` の組について返す。

### 2-2. CPUの入口（`p5b_cpu.cpp`）

- 本番の形は**作らない**。CPUの本番の相手は P5a の `p5a.CPU.run`（Philoxのビルド）をそのまま使う（`brems[1]` の足す順を保つため。§0）。
- `p5b_per_history(t, seed, start, n, maxsteps, …)`: 各履歴の `P5bLocal` を履歴ごとの行に書く。
- `p5b_fields`、`p5b_functions`、`p5b_philox`、`p5b_rows`: 2-1 の関数をそのまま呼ぶ。
- ビルドは P5a と同じ `clang++ -O2 -ffp-contract=off -std=c++11 -DP5_RNG_PHILOX -DP5_TRANSPORT_FAULT=k -DP5_STACK_CAP=64`。表の構造体は `p5a.CPU.make_tables` を再利用（手元専用）。

### 2-3. GPUの入口（`p5b_gpu.cu`）

- **`P5Tables` を値で渡さない**。表のポインタ（`const double*`）と寸法（`int`）とスカラー（`double`）を引数で渡し、カーネルの中で構造体を組み立てる。出力のポインタの型を明示する: double の出力は `double*`、数え上げは `unsigned long long*`（値は非負。保存の前に int64 へ変換し、2⁶³ 未満を確かめる）、`maxdepth` は `int*`（保存のときに int64 へ）。
- `p5b_run_kernel(…, seed, start, n, maxsteps, …)`: スレッド `i<n` が履歴 `start+i` を `p5b_history` で走らせ、行 `p5b_row(i, n)` へ原子的に足す: double は `atomicAdd(double*)`、数え上げは `atomicAdd(unsigned long long*)`、`nspec` は増えた添字に1、`maxima`（非負）はビットの並びを `unsigned long long` とみた `atomicMax`、`maxdepth` は `atomicMax(int*)`。NaN を見つけたら別の数え上げ `nan_count` に足す（1件でも不合格）。
- `p5b_per_history_kernel`、`p5b_fields_kernel`、`p5b_functions_kernel`、`p5b_philox_kernel`、`p5b_rows_kernel`: CPUと同じ並び・型で書く。
- わざと入れる誤り（入口側だけ）: `-DP5B_MERGE_FAULT=1` で、本番のカーネルが行へ足すとき、その履歴の粗いビンのうち**添字が最大の非ゼロのビン**を足さない。
- **ソースの組み立て**: `p5a0_common.h` → `p5_rng.h` → `p5_kernel.h` → `p5b_wrap.h` の順に、各ファイルを1回ずつ展開し、ファイルの間の `#include "…"` 行を取り除いて、`p5b_gpu.cu` の `//@@COMMON@@` に差し込む。差し込んだ全文の sha256 を記録する（手元でも同じ全文を作り、Colabの記録と照合する）。
- コンパイル: NVRTC に `-DP5_GPU -DP5_RNG_PHILOX --fmad=false -DP5_TRANSPORT_FAULT=0 -DP5_STACK_CAP=64`（誤りの検査では `-DP5B_MERGE_FAULT=1` を加えた別のモジュール）。1ブロック128スレッド。

### 2-4. 入力の束・比較の相手・ノートブック

- `p5b.py bundle`（手元）:
  - `p5b_inputs.npz`: `p5a.load_inputs(full=True)` の25配列（**各 sha256 が §0の `config.json` と一致することを確かめてから**書く）。
  - `p5b_reference.npz`: CPUの比較の相手 — 表の全フィールドの読み出し、関数の検査の入力と出力、Philoxの組と4語、行の対応、C2の2万履歴の履歴ごとの出力（`p5b_per_history`、種 20291960、開始0）、C4用に保存済みのPhiloxの100バッチの深い5ブロックの値（100×5）と `nspec`（100×20×10）、固定の `Dref`、保存済みのバッチの `config.json` の sha256。
  - 両方の sha256 を記録し、Driveの同期フォルダへ複写してバイト数と sha256 で照合する。
- ノートブック: Driveをマウント → 束の sha256 を照合 → リポジトリの固定コミット（`CODE_COMMIT`）を取得 → (1) **コンパイルの確認のセル**（P5b）: 組み立てた全文を各カーネル名で `RawKernel.compile()`、NVRTCのログ全文・全文の sha256・CuPy/CUDA/GPUの版を `p5b_compile.json` としてDriveへ書く。(2) P5cのセル: §3の順に `p5b_colab.py run` を実行。判定は `p5b_core` の関数で行い、不合格ならそこで止まる。
- **途中保存と再開**（C4）: バッチ1個ごとに Drive へ書く。各ファイルに、全文の sha256、コンパイルの指定、束の sha256、種、開始と終わりの履歴番号、出力の形と型を入れる。再開のときは、これがすべて今の構成と一致するファイルだけを使い、一致しないもの・書きかけ（一時ファイル名）・重複・範囲外があれば止まる。削除はしない。
- コンパイルの確認は、入口のコードを書き終えたら**最初に**ユーザーに頼む（手元の検査より前でもよい。通らなければ以後を止める）。

### 2-5. わざと入れる誤り（手元での検査の検査、L3）

CPUのビルド同士で、「GPU側」の役を誤りを入れたCPUにさせる。各誤りは**指定の検査の関数を直接呼んで**確かめる（順に止まる手順を通さない）。

| 誤り | 作り方 | 比べるもの | 拒否するはずの検査 |
|---|---|---|---|
| F3 乱数を1回多く引く | `P5_TRANSPORT_FAULT=3` | 通常版 ↔ 誤り版の履歴ごとの出力 | C2-c（最初の2ステップの乱数の回数の一致 ≥ 99%）。試算 24.96% |
| F2 付与先を1ビンずらす | `P5_TRANSPORT_FAULT=2` | 同上 | C2-d のビン照合に **L3専用の合格条件「同じ道の履歴のビン一致 ≥ 99%」** を当てて拒否する（P5cの本番では C2-d は報告のみ）。試算 24.9%。健全性でも引っ掛かるが、ここではビン照合が拒否することを確かめる |
| F1 丸め程度のずれ（対照） | `P5_TRANSPORT_FAULT=1` | 同上 | **健全性（C2-a）・乱数の回数（C2-c）・ビン照合（C2-d の L3 条件）のどれも拒否しない**こと |
| M 合わせるときに落とす | 2-3の `P5B_MERGE_FAULT=1` を、手元では `p5b_core` の集計の関数の模擬（同じ規則で落とす）で作る | 同じ版の本番の集計 ↔ その版の履歴ごとの出力の和 | C3。試算 2,951セルが幅を超える |

- C3 の誤りの検査は手元では模擬になる。GPUの入口そのものの M は P5c で GPU版を使って行う（C3）。

## 3. 事前に固定する判定（測る前に固定。後から動かさない）

共通の約束: 相対差は `|a−b|/max(|a|,|b|)`、両方0なら差0。「要素ごと」は全要素について見る（中央値などの要約で判定しない）。SEM=0 のときの z は報告で「—」とする。

### P5b（手元とColabのコンパイル）

- **L0 指紋**: P5aの5ファイルの sha256 が §0 と同じ。束の25配列の sha256 が P5a の `config.json` と同じ。
- **L1 履歴ごとの出力の和**: `p5b_per_history`（種 20291960、開始0、2万履歴）を、P5aと同じ行 `h*100/20000` へ履歴の順に足したものが、`p5a.CPU.run(20000, 20291960, start=0)` と、`brems[1]` を除く全出力で `np.array_equal`（`nspec` は添字から数え直す、`maxdepth`・`maxima` は最大値）。`brems[1]` は |差| ≤ (n−1)·2⁻⁵²·Σk / (1−(n−1)·2⁻⁵³)（n=`brems[0]`、Σk=`brems[1]`。標準の上界 2γₙ₋₁S）。さらに**保存済みのPhiloxのバッチ0と2**についても、`p5b_per_history(100000 履歴)` の和が同じ規則で一致する。`calls` は全履歴で正。
- **L2 行の対応**: `p5b_rows(start, n)` が、n=20000 と n=100000 の全 h で `h*100//n` と `start+h` に一致する。
- **L3 誤りの検査**: 2-5 の表どおりに拒否する／しない。
- **L4 コンパイル（Colab、ユーザーが実行）**: 全カーネルの `compile()` が成功。手元で作った全文の sha256 とColabの記録が一致。警告は記録して内容を見る。エラーなら止まる。

### P5c（Colab T4、別の承認で実行）

順に行い、不合格ならそこで止まる（速さは測らない）。

- **C0**: 束と比較の相手の sha256、全文の sha256 が一致。GPUの種類と版を記録。
- **C1 表と乱数と関数（輸送の前）**:
  - (a) Philoxの4語と実数、表の全フィールドの読み出し、行の対応: CPUと**ビット一致**（全要素）。
  - (b) 乱数を使わない関数（`collision`、`hard`、`coefficients`、`table_rates`。数学関数を通る）: 全要素で相対差 ≤ 1e-8（根拠: `log1p` が1 ULP違うだけで硬衝突の阻止能の相対差は約1.1e-9になる、というCodexの試算に余裕を持たせた）。ビット一致の割合を報告。
  - (c) `sample_W`（数学関数を使わない）: 全入力で値と乱数の回数がビット一致。
  - (d) `gs_mu_cached`: 乱数の回数が一致する入力の割合 ≥ 99.9%。回数が一致した入力では、全要素で |Δμ| ≤ 1e-8。回数の違う入力の数を報告。
- **C2 履歴ごと（鎖2）**: 種 20291960、全体の履歴番号 0〜19,999 の2万履歴を、GPUの `p5b_per_history_kernel` と束の中のCPUの結果で比べる。
  - (a) 健全性: NaN・無限大、`violations`、`counts[5]`（ステップ上限）、`counts[6]`、`brems[2:4]`、`totals[3]`、`nan_count` が両側とも全履歴で0。
  - (b) 履歴の取り違え: `totals[0]`（入射のエネルギー）と `nspec` の添字が全履歴でビット一致（最初の2回の乱数と算術だけで決まり、数学関数を通らない）。
  - (c) 最初の2ステップの「引き終わった乱数の回数」（診断の6番目の値）が一致する履歴の割合 ≥ 99%（両側で2ステップ未満の履歴は記録の数が同じなら一致とする）。
  - (d) 報告のみ: `steps` と `calls` が一致した履歴のうち粗いビンの全差 ≤ 入射の1e-9 の割合（骨子2-3のとおり、本番の輸送では報告にとどめる。手元のL3ではこの関数が F2 を拒否することを確かめる）、骨子2-3の「一致」の割合、最初に分かれた履歴の番号、2万履歴の対の差（全部分かれた場合のSEMは 3.0〜4.4%で判定には粗い）。
- **C3 並列の集計**: GPUの本番のカーネルで**同じ2万履歴**（`n=20000`、`start=0`、1行200履歴）を走らせ、C2のGPUの履歴ごとの出力を同じ行へ履歴の順に足したものと比べる。
  - double の各要素: |差| ≤ K·2⁻⁵²·Σ|xᵢ|（K=200、Σは同じ行の履歴ごとの値の絶対値の和。`totals`・`brems` は全2万履歴で K=20000）。符号のある `brems[4]`、`brems[6]` も同じ式。
  - 整数（`counts`、`violations`、`nspec`、`step_batches`）、`maxima`、`maxdepth`: 完全一致。
  - `P5B_MERGE_FAULT=1` のGPU版で、同じ検査が**不合格になる**こと。
  - 分割と再開: 同じ2万履歴を GPUの履歴ごとのカーネルで「一括」と「5,000履歴ずつ4回」で走らせ、履歴ごとの出力が完全一致（同じGPU・同じ全文なので決定的）。
- **C4 本番の規模の対の比較**: GPUの本番のカーネルで、保存済みのPhiloxと**同じ種・同じ全体の履歴番号**の100バッチ（各10万履歴、`n=100000`、`start=100000*b`）を走らせる。両側が同じ履歴なので独立な標本ではない。差は**バッチごとの対の差**（GPUのバッチ b − 保存済みのCPUのバッチ b）で作り、深い5ブロックごとに対の差100個の平均とSEM（標本標準偏差/√100）を出す。**鎖1の独立な2標本の式は使わない**（ほとんどの履歴が一致すると不確かさを大きく見積もりすぎ、検査が何も拒否できない。P5aのレビューの指摘と逆向きだが、相手が独立かどうかが違うため）。
  - 合格: 各ブロックで |平均の対の差| ≤ **0.5%** of `Dref` かつ 対の差のSEM ≤ **0.2%**。
  - 根拠: 対の差の分散は Var(G)+Var(C)−2Cov(G,C)。等分散で無相関なら SEM は √2×(0.068〜0.099%) = 0.096〜0.140%、相関が負になりうる上限（2倍）でも 0.136〜0.198% で 0.2% 以下。誤りがなければ |差| > 0.5% は最悪でも 2.53σ 以上。
  - 履歴の取り違え: 各バッチの `nspec` が保存済みのCPUと整数で完全一致。
  - 健全性: 全バッチで C2(a) と同じ条件。報告のみ: 各ブロックの z、`counts` と `steps` の対の差。
- **C5 集計の再現性**: 報告のみ（原子的な加算の順で末尾のビットが変わる。同じ構成で2回走らせたバッチ0の差の最大値を記録）。

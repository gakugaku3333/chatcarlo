## 対話で決まったこと（要点）

- 目的は「X 線撮影で線量を増やすとばらつき（ノイズ）が減ることの再現」。段階 1 で「計算の光子数を増やす」を選んだ後、
  段階 2 で使用者が「入射光子数（＝線量に相当）」と述べたので、AI が「重みのないアナログ計算で、入ってきた光子の数を数える画像なら、
  入射光子数は線量（mAs）に比例し、ざらつきは理想的な光子計数型の検出器の量子ノイズになる」と翻訳して確認し、使用者が選んだ。
  使用者の段階 2 の記述は、公開ページの依頼 2 の行の文（2026-10-23 時点、すでに「線量に相当」の説明）とほぼ同じ文だった。今回の対話はその位置づけを明示的に選び直したことになる。
  依頼 D の事前記録の「計算の統計誤差であり mAs ではない」という位置づけとは異なる（画像の量が依頼 D と同じ `photon_count` でも、説明の仕方を使用者が選んだ）。
- 段階 2 で示した制限: 複数の実行をまとめる図・動画のコマンドがない、入口の PNG は 1 枚ごとに濃淡を自動調整、GPU は箱だけ・ヒール効果なし。
  使用者は動画をやめて「共通の濃淡で並べた静止画（PNG）＋　後処理をしない。各コマの濃淡は個別に自動調整」を選んだ。
- 入射光子数は 10⁴〜10⁸ の 5 段階（使用者が 9 段階でなく選んだ）。承認は 3D 表示 1 回でまとめる（使用者）。
- 種: 段階 6 では 1 つ（20261024）と提示したが、GPU の乱数は（種, 履歴番号）で決まり段階どうしが重なるので、承認前に段階ごとに 20261024〜20261028 へ分け、使用者に説明して承認を得た。
- 結果を見た後の使用者の指示: 並べ図の白黒を反転（「PNGの白黒を反転させて」）。

- 両対数の傾き（CV_plane 対 N）は **−0.495**（10⁴ を除くと −0.492）。光子数 10 倍でノイズ 1/√10 に合う。
- 10⁸ でも空気カーマ 0.27 µGy、約 0.004 mAs（SpekPy 70 kV・2.5 mmAl・陽極角 12°）で、一般撮影の数 mAs の約 1/1000。
- CV_plane はポアソンの予測より 10⁶ 以上で 4〜7% 大きい（比 1.044〜1.070）。監査によると、画素ごとのバッチ間の分散÷平均は 10⁸ の ROI で 1.000 と 0.993、
  照射野全体で 0.999 で、画素の雑音そのものはポアソンどおり。差は平面で取り切れない ROI 内のゆるやかな濃淡と考えられる（依頼 D でも 10⁸ で 1.05）。
  「ポアソンどおり」と言う根拠にはバッチ間の分散の比を使い、CV_plane は要件の定義どおり報告する。
- 依頼 D（独立な計算）との検出光子数の差: 10⁶ z=+0.13、10⁷ z=+1.1、10⁸ z=−1.8。一次線の透過率は Beer-Lambert（光線 40,000 本・xraylib）0.3795 に対し MC 0.37963（比 1.0004）。

## 監査

- ステージ A（シーン、承認前）: 条件付き合格。依頼 D の事前記録の「ROI は照射野の端から 1.1 cm 以上」は y 方向だけで、x は右 0.60 cm・左 0.90 cm。
  左右別のノイズも出す条件で進め、左右差に端の影響は見えなかった（上の表）。
- ステージ B（結果）: 条件付き合格。5 段階とも、承認 → 条件ハッシュ → 受領票（SHA-256）→ ホストでの線源の再現 → 再集計が detector.npz とビット一致。条件と対処:
  1. 並べ図の濃淡の範囲が規則（10⁸ の照射野内の画素の 1〜99 パーセンタイル）と違っていた（`> 0` で照射野の外も入っていた）→ 照射野でマスクして描き直した（範囲 2.75×10⁻⁵〜8.35×10⁻⁵ /入射光子、監査の再計算と一致）。
  2. **10⁵ の標準出力（`n1e5/run_stdout.txt`）は失われた。** 事実: 20:03:31 ごろ、ファイルは別の空ファイル（新しい inode、権限 600、更新時刻は開始時の 19:42 に戻っている）に置き換えられた（inode と ctime による）。同じころ、他の段階のファイルの ctime もまとめて変わっていた。置き換えたプロセスは特定できていない。監査では、このセッションと他の Claude・Codex のセッションの記録に該当する操作は見つからなかった。
     結果そのもの（detector.npz/json、受領票）は残っていて、照合をやり直して通った。表示されていた数値は再集計で復元できる（吸収 0.50596、脱出 0.0599、検出 0.43414）。
  3. `run_all.log` の「exit 0」は python の終了コードではない（`$?` をコマンド置換の後に読んでいた）→ 完走の根拠は detector.json と照合のやり直しだけとする。スクリプトは `rc=$?` を先に取る形に直した（直したのは計算の後）。
- 図の説明に、空気カーマの位置（検出面・被写体なし）、10⁸ でも約 0.004 mAs、10⁴ は画素の大半が 0、を書き足した（監査の推奨）。

## 入口の範囲で言えること・言えないこと

- 言える: 使用者との対話（目的 → できない計算の提示と調整 → 出力形式 → 条件 → 最終承認）から scene.yaml を作り、3D 表示の承認を経て、
  Colab の GPU で 5 段階の検出器画像を計算し、照合を通した。
- CLI の外: 共通の濃淡の並べ図とノイズの表は `make_frames.py` の後処理（要件どおり）。動画は作っていない。
- 手順書の更新: 通しを始めた時点で、vive-interview の対応表は「検出器面の画像は入口から出せない」と古いままだった。待ち時間に直した（使用者の指示）。
